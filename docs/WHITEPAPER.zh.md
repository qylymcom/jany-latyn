## 摘要

Jany-Latyn是一种由28个字母构成的柯尔克孜语拉丁正字法，与一个确定性的转换器和一个试验场一同发布；在试验场中，每一项有争议的选择都是可以选择的选项。它的首要约束是：每一种拼写都必须能按规则由西里尔字母计算得出，无需借词词表，从而使过去86年的文本能够无人值守地完成转换，而转换器的输出本身就是正确的Jany-Latyn。这一约束确定了其余字母所依赖的那几个字母。柯尔克孜语西里尔字母只写一个`к`和一个`г`，若把其中任何一个拆分为一个软腭音字母和一个小舌音字母（`k`/`q`，`g`/`ğ`），就需要知道哪些词是借词，因此Jany-Latyn只保留一个`k`和一个`g`。这样一来，前后对立就只由元音承担，于是`ы`写作`y`，而不写作无点`ı`，因为后者在大小写转换中和在ASCII中都会失去与`i`的区别；`y`既已占用，滑音`й`就写作`í`。其余的对应为：`ж→j`、`ч→ç`、`ш→ş`、`х→h`、`ң→ŋ`、`ө→ö`、`ү→ü`；元音长度用双写表示，俄语的硬音符号和软音符号被吸收进滑音，因此每个词都是一个单一的纯字母词元。两种语域被一并规定：带附加符号的完整形式，以及供未经改装的键盘使用的ASCII简易形式。本文还确定了机器所需、而正字法提案通常略去的内容：一种其损失事先说明而非事后发现的反向转换，一个横跨两种形式的搜索折叠键，以及一套字母顺序及其排序定制。

# 第一部分——Jany-Latyn简述

Jany-Latyn是为柯尔克孜语提出的一套拉丁字母：共28个字母，其设计使计算机能够把任何西里尔字母柯尔克孜语文本自动转换过来，既不需要借词表，也不需要任何人核对结果。转换器写出的就是正确的Jany-Latyn。这个名称本身就是用下文所述的简易形式书写的；其完整形式为*Jaŋy Latyn*，即“新拉丁”。

这条规则决定了塑造其余部分的两个字母。柯尔克孜语西里尔字母只有一个`к`和一个`г`，因此Jany-Latyn只保留一个`k`和一个`g`，不用`q`或`ğ`：把它们拆开就必须知道哪些词是借来的（是*kosmos*，而不是*qosmos*）。只有一个`k`，就只能靠元音来区分*кы*和*ки*，所以`ы`需要一个不会与`i`混淆的字母：用`y`，而不用无点`ı`，因为后者在大写时、在小字号中以及在普通键入中都会失去与`i`的区别。`y`既已占用，`й`就得到了自己的字母：`í`，即加了一个符号的`i`，正如`й`是加了一个符号的`и`。

其余部分都很熟悉：`j`表示`ж`，如*Japarov*和*Jalal-Abad*；`ö`、`ü`、`ç`和`ş`，与土耳其语、阿塞拜疆语、土库曼语以及通用突厥语字母相同；`ŋ`，形似`ң`；长元音双写，与西里尔字母相同。去掉符号，结果就是任何键盘都能输入的简易形式：*jaŋy*变成*jany*。

Jany-Latyn并不主张更改国家字母。它为人们每天都已经在键入的拉丁字母柯尔克孜语提供一种有文档说明的写法，而且它已经可以运行：一个能把柯尔克孜语固有词汇准确还原为西里尔字母的双向转换器、若干键盘布局，以及一个可以在真实文本上试用每一种替代方案的试验场。

## 1. 问题所在，以及Jany-Latyn提供什么

无论国家层面发生什么（第三部分），非正式的拉丁字母转写都已是日常。柯尔克孜语使用者每天都在即时通讯、代码、社交媒体、商业往来和侨民交流中书写拉丁字母，没有标准，差异相当大：`ү`被写成*u*、*y*、*v*或*w*；`ө`写成*o*、*oe*，甚至写成数字*8*；`ж`写成*j*、*zh*或*dj*；`ң`写成*n*或*ng*；元音长度则因书写者而异，或用单个字母，或用双写，或在后面加*h*。这种差异正是本项目首先要解决的问题，因为无论国家政策如何，它都是今天就存在的问题。

**Jany-Latyn**提供两样东西：

1. **一套正字法**，为现在就能键入和阅读而构建：拉丁字母`ö`和`ü`；带下加符的咝音`ç`和`ş`；`j`表示浊塞擦音；`ŋ`表示软腭鼻音；`y`表示闭后不圆唇元音；用双写表示音位长度；`í`在所有位置上表示硬腭滑音。
2. **一个试验场**，其中每一项有争议的选择都是一个开关。可以互换`ı`和`y`，开启音位变体`q`，把每个`ж`都写成`c`，把咝音切换为二合字母，用`ñ`代替`ŋ`，或在行内显示西里尔字母`ө`和哈萨克语的`ұ`，然后在每种配置下阅读同一段文本，评判结果。

有两项承诺决定了其余部分。该正字法以**两种语域**而非一种来规定：一种是带附加符号的**完整形式**，一种是供未经改装的键盘使用的ASCII**简易形式**；二者一并定义，因此谁都不是对方的权宜之计（§19）。此外，它的规定做到了机器所需的程度：说明了损失的反向转换、单一的搜索折叠键，以及带排序定制的字母顺序（§17、§18以及附录B—C）。

最重要的是，Jany-Latyn被设计为**可由西里尔字母推导**。这一约束比任何审美偏好都更能解释下文的大部分内容，包括作者若从一张白纸起步本会作出不同选择的那些地方（§8）。

### 1.1 本系统的用途

Jany-Latyn有两种预期用途，二者的方向略有不同：

- **一种转写标准**，用于已经以西里尔字母存在的文本，旨在无需人工干预地处理语料库、档案、地名和数据库。
- **一种候选正字法**，用于直接以拉丁字母书写柯尔克孜语，无论是今天的非正式书写，还是将来某个时候的正式书写。

当二者冲突时，以转写用途为准。理由很实际：一个无法自动处理现有86年西里尔字母文本的提案，从一开始就等于抛弃了语料库。这就是为什么`k`是统一的，而不是拆分为`k`/`q`（§8）；为什么借词中的滑音被并入其他地方所用的同一个`í`（§15.1）；以及为什么反向转换被定义为优先照顾柯尔克孜语固有词汇而不是俄语借词（§18.1）。

### 1.2 Jany-Latyn要求什么，不要求什么

Jany-Latyn不主张国家层面的文字转换。它是探讨这一问题的工具，也是使已经存在的非正式书写更加一致的工具。即使国家层面的问题要再过50年或100年才解决，或者永远不会解决，本项目仍然有用：今天有数以百万计的柯尔克孜语使用者在没有任何约定的情况下键入拉丁字母，一套有文档说明的约定本身就值得拥有，与任何法令无关。

这样定位并不是修辞上的回避。它改变了设计。一个寻求立法的提案可以假定有课程、执行机制和一个负责维护借词表的机构，因此它承担得起词表依赖（§8），也就承担得起`q`。一个在有人打开代码仓库的那一刻就必须能用的提案则承担不起，它必须可推导、无需词典，并且能在现有硬件上键入。

## 2. 字母表一览

Jany-Latyn有28个字母，顺序如下（§17）：

**A B Ç D E F G H I Í J K L M N Ŋ O Ö P R S Ş T U Ü V Y Z**

**a b ç d e f g h i í j k l m n ŋ o ö p r s ş t u ü v y z**

**标记说明**。斜体表示拼写。方括号表示以国际音标记写的读音，其中[y]是`ü`的音，[ɯ]是`ы`的音，因此*kyz*（кыз，“女孩”）与[kyz]，即*küz*（күз，“秋天”）的读音，是不同的词。括号中的西里尔字母给出源拼写。

有14个字母无需说明：每个字母在各种形式中写法都相同，如*bala*（бала，“孩子”）和*dos*（дос，“朋友”）。下表列出其余22个西里尔字母，每个都给出其Jany-Latyn形式、简易形式和一个例词。

## 3. 背后的规则：设计原则

| 原则 | 目标 | 收益 |
| :--- | :--- | :--- |
| **1. 西里尔字母可推导性** | 每一个Jany-Latyn形式都可以按规则由西里尔字母计算得出，无需词表。 | 现有语料库可以自动转换；没有任何词需要由人来决定。 |
| **2. 输入的人机工效** | 在标准ANSI/ISO键盘上快速键入。 | 死键、修饰键层或长按都很少。 |
| **3. 音系经济性** | 可预测的音位变体不另设字母。 | 字母更少，音位准确性没有损失。 |
| **4. 字体排印与计算上的稳定性** | 单一文字、标准码位、预组合形式。 | 词中不发生字体回退，没有跨文字排序，大小写转换可以预测。 |
| **5. 设计上的两种语域** | 带附加符号的完整形式与ASCII简易形式，一并规定。 | 在印刷品中和在任何未经改装的键盘上都易于辨读。 |

原则1是其他原则据以调整的约束。原则5在§19中阐述，它是本系统中最容易被误认为局限的部分。

要看清这一约束，最容易的办法是看一个替代字母与Jany-Latyn可能存在的两种不同。*替换*是把某个西里尔字母在其出现的每个地方都写成另一个形状：用`ñ`表示`ң`，用`ı`表示`ы`，用`ch`表示`ч`。转换器可以自行施行替换，试验场也提供了许多替换。*拆分*则是视词而定，把一个西里尔字母变成两个拉丁字母：把`к`变成`k`或`q`，把`г`变成`g`或`ğ`，把`ж`变成`c`或`j`。柯尔克孜语西里尔字母并不标明哪些词是借来的，因此只有借助一份标明了这一点的词表，才能正确地施行拆分；若仅凭规则施行，它就会把*космос*写成*qosmos*。§8把这称为词表依赖。

Jany-Latyn的拼写不包含任何拆分。因此，转换器写出的就是正确的Jany-Latyn，不需要维护一个经人工校正的第二版本。同一原则也解释了为什么没有`q`、`ğ`和`c`（§8、§11），以及为什么三个待评估字母`ä`、`x`和`w`——它们都属于拆分——可以由直接书写拉丁字母的人使用，却永远不会由转换器生成（§20）。系统中唯一的词表朝另一个方向起作用：一组可选的借词，其西里尔字母拼写无法按规则还原，只在转换回西里尔字母时才会查阅（§18.2）。

## 4. 塑造其余部分的字母

**一个`k`和一个`g`**。在柯尔克孜语中，小舌音[q]和[ʁ]是/k/和/g/的位置变体，可以由词中的元音预测，而柯尔克孜语西里尔字母从未把它们分开书写。写出`q`和`ğ`将是一种拆分：把*кар*变成*qar*的元音规则，也会把借词*космос*变成*qosmos*，只有词表才能阻止它。作者本人偏爱`q`，理由是音系上的和历史上的；Jany-Latyn保留一个`k`和一个`g`，是因为它由可推导性定义（§8）。

**用`y`表示`ы`**。只有一个`k`，就只能靠元音来区分*кы*和*ки*，所以`ы`需要一个不会与`i`混淆的字母。无点`ı`与`i`只差一个点，而这个点在小字号中会丢失，在土耳其语和阿塞拜疆语区域设置以外会在大写时被合并（*kırgız*转为大写后成为`KIRGIZ`），简易形式和搜索折叠也会把它去掉。`y`在任何地方都保持区别，而且它正是该国英文国名中已用来表示`ы`的字母（§9）。

**用`í`表示`й`**。`y`既已用于`ы`，滑音就需要一个自己的字母。若也写成`y`，*тыйын*就会坍缩成`tyyyn`；若用不带符号的`i`，*бийик*就会变成条形码般的`biiik`。`í`是加了一个符号的`i`，正如`й`是加了一个符号的`и`，并且它在每个位置上写法都相同：*toí*、*tyíyn*、*biíik*（§10）。

**用`j`表示`ж`**。柯尔克孜语西里尔字母用同一个`ж`既表示固有词的塞擦音[dʒ]，也表示借词中的[ʒ]，因此需要的是一个字母，而不是两个。Jany-Latyn采用`j`，即官方罗马化和护照上已用来表示`ж`的字母（*Japarov*、*Jalal-Abad*）；CTA把它拆分为固有词用`c`、借词用`j`，这同样需要一份词表（§11）。

## 5. 它带来什么，又付出什么代价

### 5.1 它带来什么

- **无需校正步骤**。任何西里尔字母柯尔克孜语文本，从档案到地名登记册，都可以一遍转换完毕，结果是正确的Jany-Latyn，而不是一份有待校对的草稿（§3）。
- **柯尔克孜语固有词汇可准确往返**。转换回西里尔字母时，每一个固有词都能还原；只有部分借词的拼写被简化（§18.1）。因此，拉丁字母和西里尔字母可以并行使用，而一个多语国家无论如何都需要这样（§22.6）。
- **柯尔克孜读者猜得到的字母**。`j`如*Japarov*和*Jalal-Abad*中那样；`y`如该国英文国名中那样；`ö`、`ü`、`ç`和`ş`如土耳其语、阿塞拜疆语、土库曼语和CTA中那样；`í`和`ŋ`呼应`й`和`ң`；长元音像西里尔字母那样双写（§22.4）。
- **在任何人接受教学之前，误读更少**。读者看到标牌时，会按已知的读音来读基本字母。*Чыгуу*（出口）写作`ÇYGUU`，可能在一个字母上造成误导，即`C`对应`ч`；对齐CTA的`ÇIĞUU`又增加了第二个，即`I`对应`ы`，而若按西里尔字母的读音来读，它会使公共标牌上最常见的词之一变成粗话（§22.4）。
- **在软件中安全**。大写永远不会改变词（`KYRGYZ`不会变成`KIRGIZ`），没有撇号会在搜索或选取时把一个词断开（§16），而且简易形式同时也是搜索键，因此搜*jany*能找到*jaŋy*（§19、附录B）。
- **更容易被找到，作为一项预测**。*kylym*和*jaŋy*这样的拼写不属于任何其他语言，而对齐CTA的*qılım*同时也是阿塞拜疆语的一个动词形式，*canım*（жаным）则是土耳其语（§22.2）。这是作为一项有待检验的预测提出的，而不是作为这些选择的理由（§23.2）。
- **现在就能用**。不需要国家作出任何决定，转换器、键盘布局和试验场都已在运行（§7、附录D）。

### 5.2 已知局限

- **拉丁字母→西里尔字母的转换对俄语借词是有损的**。柯尔克孜语固有词汇可准确往返；仅存在于借词中的区别（`ц`、`щ`、`ё`与`йо`之别、`ъ`、`ь`）在往返转换中无法保留。这是有意的设计，§18.1对此有精确规定。
- **简易形式是单向的**。以ASCII书写的文本无法被机械地还原为完整形式或西里尔字母（§19）。
- **`ŋ`在手机上的可用性参差不齐**。在美国区域设置下的安卓键盘上，可以通过长按菜单输入它（经作者确认）；iOS上的情况尚未核实。在没有它的地方，简易形式把它写作`n`（§19）；`ñ`作为一种对照设置提供（§14）。
- **方言覆盖不完整**。有三个扩展字母（`ä`、`x`、`w`）供评估，但没有一个属于Jany-Latyn（§20）；其他方言特征则完全没有体现。
- **尚无任何教学法**。这里的一切都还没有在学习者中、课堂上或手写中检验过。

## 6. 与其他方案的比较

Jany-Latyn在对辨识度最重要的那些字母上与BGN/PCGN——吉尔吉斯斯坦用于地理名称的罗马化方案——一致，即用`j`表示`ж`，以及`ö`和`ü`，但它是为了让柯尔克孜语使用者书写而构建的，而不是为外国读者转录（§21.1）。它与2024年在巴库商定的通用突厥语字母共有`ö`、`ü`、`ç`和`ş`，而在六个字母上与之分歧，每一个都在第二部分中论证（§21.2）。它与瑟尔特拜·穆萨耶夫（Syrtbai Musaev）的28字母草案共有同样这四个字母以及用`y`表示`ы`；该草案复兴了特内斯塔诺夫（Tynystanov）1928年的字母表，恢复了`k`/`q`拆分，把`ж`写作`c`，并用`ņ`标记软腭鼻音（§21.3）。

| 西里尔字母 | BGN/PCGN | CTA | **Jany-Latyn** |
| :---: | :---: | :---: | :---: |
| ж | j | c | **j** |
| й | y | y | **í** |
| ы | y | ı | **y** |
| ң | ng | ñ | **ŋ** |
| ө | ö | ö | **ö** |
| ү | ü | ü | **ü** |
| ч | ch | ç | **ç** |
| ш | sh | ş | **ş** |
| х | kh | h | **h** |

（据§21.1中的表格压缩而成，该表另列有ALA-LC和ISO 9。）

在本文中，“Jany-Latyn”始终指所提出的字母表。试验场能显示的其他每一种配置，包括像用`ñ`表示`ŋ`这样的单一替换，都是一种*对照设置*：要在同一段文本上与Jany-Latyn对照评判的东西，而不是它的一个变体。有三种对照设置在全文中反复出现，每一种都比前一种离Jany-Latyn更远一步。短语*аңкыгый жигит*（“一个笨拙的小伙子”）包含了它们所改变的每一个字母：

| 设置 | 相对Jany-Latyn的改动 | *аңкыгый жигит* | 是否需要词表？ |
| :--- | :--- | :--- | :---: |
| **Jany-Latyn** | — | **aŋkygyí jigit** | 否 |
| q+ğ | 在后元音词中用`q`表示`к`，用`ğ`表示`г` | aŋqyğyí jigit | 是 |
| q+ğ+ı | 另外用`ı`表示`ы`，用`y`表示滑音`й` | aŋqığıy jigit | 是 |
| 对齐CTA（q+ğ+ı+c+ñ） | 另外用`c`表示固有词的`ж`，用`ñ`表示`ң` | añqığıy cigit | 是 |

最后一列用一行概括了§3的论点：超出Jany-Latyn的每一种设置都包含拆分，而拆分只有借助词表才能写对。*Жигит*是前和谐词，因此即使在写`ğ`的地方，它的`г`仍为`g`；在q+ğ+ı一行中，它的`и`仍为`i`，与`ı`并存。每种设置下的真实词语和一段连续文本见§21.2，各字母表的并列对照见§17.3。

## 7. 试验场

一个客户端应用程序提供一键预设——Jany-Latyn基准与对齐CTA的设置（`ı`表示`ы`，`y`表示滑音，`c`表示`ж`，`q`和`ğ`，以及`ñ`表示`ң`）相对照——并为第二部分所论证的每个变量提供可选的选项：

| 变量 | 选项 | 论证见 |
| :--- | :--- | :---: |
| 前圆唇元音 | `ö/ü`（Jany-Latyn）、`ө/ü`、`ө/ұ`、`ө/ū` | §12.1、§12.2 |
| 咝音 | `ç/ş`（Jany-Latyn）、`ch/sh` | §13 |
| 塞擦音`ж` | `j`（Jany-Latyn）、`c`——CTA的取值，用于借词时属于机械对应 | §11 |
| 借词符号`ъ`/`ь` | 吸收进滑音（Jany-Latyn）、撇号 | §16 |
| 软腭鼻音 | `ŋ`（Jany-Latyn）、`ñ` | §14 |
| 滑音 | `í`（Jany-Latyn）；`ĭ`和`ĩ`作为带符号的替代形式；不带符号的`i`，即被否定的条形码映射；`y` | §10、§9 |
| 后不圆唇元音 | `y`（Jany-Latyn）、`ı` | §9 |
| 小舌塞音 | 统一的`k`（Jany-Latyn）、音位变体`q` | §8 |
| 小舌擦音 | 统一的`g`（Jany-Latyn）、音位变体`ğ` | §8 |
| 表示`х`的字母 | `h`（Jany-Latyn）、`x`——每个`х`都写作`x`，供认为软腭音值更好的读者使用；并非下面那种拆分 | §20 |
| ASCII备用形式 | 去除符号为`c/s`（Jany-Latyn）、扩展为`ch/sh` | §19 |
| 扩展字母 | 关闭（Jany-Latyn）；`ä`、`x`/`h`、`w`各自可单独选择——直写模式，正向转换永远不会生成 | §20 |

一个并排检查器可以在真实文本上运行任意组合。

为方便起见，有几个选项是联动的。选择`ı`也会开启`q`、`ğ`和`y`滑音：`ы`写作`ı`后，`y`就空了出来，而如果保留`í`，就会让`ı`、`i`和`í`作为三个只靠符号区分的字母并列（§17.3）。选择`q`会连带`ğ`，切换回去则会撤销每一项联动。这些联动只为选项设定初始值，因此`ı`配`k`、`q`不配`ğ`、`ı`配`í`滑音，都仍然可以通过事后设置选项来实现；唯一的限制是，只有当`ы`写作`ı`时才提供`y`滑音，否则二者会冲突。引擎本身接受任何组合。当`ĩ`滑音与`ñ`组合使用时，试验场也会发出警告，但不加阻止，因为这样同一个波浪符就会承担两种无关的作用。SPEC.md第7节完整列出了这些联动。

这些开关并不是一份同样有效的内部体例菜单。每一个开关之所以存在，是为了让反例可以生成出来，而不是被描述：`q`把*kosmos*变成*qosmos*，`ı`展示大写转换对结果的影响，西里尔字母`ө`可以被打开，输出可以作为一份名单来排序。

本项目作为一项寻求证伪而非寻求采纳的提案来运作：每一项有争议的选择都已实现，全部源代码公开，托管的试验场记录读者选择了哪些配置，以便把分布情况与论证并列发表，而一个引擎损坏柯尔克孜语固有词汇的可复现案例，比赞同更有分量（§24）。

# 第二部分——逐个字母的论证

## 8. 一个`k`和一个`g`：元音和谐律制约的音位变体

有几种突厥语正字法用不同的字母表示小舌塞音[q]和小舌擦音[ʁ]。在柯尔克孜语中，它们是位置性的音位变体，可以由词中的元音预测：

| 和谐环境 | 元音 | 音位 | 实现 | 字素 | 例词 |
| :--- | :--- | :---: | :--- | :---: | :--- |
| 后 | a, o, u, y | /k/ | 小舌塞音[q] | **k** | *kar*（кар）[qar]、*kyz*（кыз）[qɯz] |
| 后 | a, o, u, y | /g/ | 小舌擦音[ʁ] | **g** | *aga*（ага）[aʁa]、*kyrgyz*（кыргыз）[qɯrʁɯz] |
| 前 | e, i, ö, ü | /k/ | 软腭塞音[k] | **k** | *kel*（кел）[kel]、*küz*（күз）[kyz] |
| 前 | e, i, ö, ü | /g/ | 软腭塞音[g] | **g** | *gül*（гүл）[gyl]、*egemen*（эгемен）[egemen] |

柯尔克孜语使用者读*kar*时会自动发出[q]；在那里发前部的[k]会违反该语言的音位配列。把二者分开书写，等于把说话者早已在运用的规则编码出来。土耳其语出于同样的理由，对`k`和`g`作出了同样的选择，尽管它为一种相关的区别保留了`ğ`。

作者本人偏爱`q`。在音系上它是更忠实的字母，它是突厥语世界和阿拉伯字母世界的大部分地方会选用的字母，而且它在柯尔克孜语中尤其具有实实在在的历史分量。尽管如此，Jany-Latyn仍然统一了`k`和`g`，其理由是原则1，而不是认为`q`是错的。

如果写`q`，与之对应的浊音也就随之而来：*egemen*有前部的[g]，*kagyluu*有后部的[ʁ]，而凡是拆分了清音这一对的系统，也都拆分了浊音那一对。特内斯塔诺夫1928年的字母表在`k`和`g`之外还有`q`和`ƣ`[[4]](#ref4)，CTA有`q`和`ğ`[[8]](#ref8)，2021年的哈萨克字母表用带短音符的ğ表示`ғ`[[5]](#ref5)。有`q`而无`ğ`的系统是可能的，因为元音预测`g`正如预测`k`一样，但没有什么理由为它辩护：产生`qosmos`的那条规则同样会产生`ğaz`、`ğaloş`、`mağazin`和`proğramma`，而只有借词词表才能阻止其中任何一种。这两个字母的区别只在于它们给哪一层造成负担。`q`是一个ASCII键，会保留在简易形式中；`ğ`是带附加符号的字母，在那里会折叠回`g`。**因此，本系统的立场是：`q`蕴含`ğ`**。Jany-Latyn对二者都不采用，而试验场把它们保留为相互独立的开关，以便仍然可以考察这种不对称的配置。

有三点考虑使Jany-Latyn坚持统一的`k`和`g`：

- **可由西里尔字母推导**。柯尔克孜语西里尔字母从来没有单独的`қ`[[4]](#ref4)，因此任何不同时知道哪些词是借词的规则，都无法从源文本中还原出`q`。请注意其中的历史细节：这一合并并非特内斯塔诺夫所为。他的阿拉伯字母改革和他的拉丁字母都区分这两个音[[4]](#ref4)。单一的`К`是随着1940年的西里尔字母而来的，那时他已在清洗中被处决两年。无论这一决定是谁作出的、出于什么原因，此后86年的读写文化都建立在它之上。
- **借词**。现代柯尔克孜语吸收了*kosmos*、*karta*、*bank*、*respublika*，它们都带有普通的欧洲式[k]，从不读[q]。和谐规则无法把它们与固有的后和谐词干区分开来：它会产生`qosmos`、`qarta`，以及像`respublikalıq`这样的混合和谐杂交形式，而正确的是`respublikalyk`。除了一份持续维护的借词词表之外，没有干净的解决办法。称之为**词表依赖**：一条在有某种东西知道哪些词是借来的之前就无法施行的拼写规则。一个有国家支持、背后有研究所和预算的标准可以承担这种依赖。一个必须无人值守地处理整个档案的转换器则承担不起。
- **经济性**。要教的字母、要在键盘上够到的字母都少两个。

最有力的反驳来自另一个方向。由于借词在后元音词中保留软腭音[k]，[k]和[q]在现代柯尔克孜口语中可以说已经形成对立（*kosmos*对*koş*），而这正是音位变体变成音位的典型情形。如果这一分析是对的，那么一个由人书写、而非由机器推导的未来标准，就应当采用`q`。地名使这一点更加尖锐：*Каракол*和*Каракөл*是两个不同的城镇，写作`Karakol`和`Karaköl`时相差一个字母，写作`Qaraqol`和`Qaraköl`时相差两个。Jany-Latyn的立场比“q是错的”更窄：它的立场是，`q`在没有词表的情况下无法由西里尔字母推导出来，而本系统是由可推导性定义的。

和谐规则的可靠程度，也只取决于它所读取的元音。西里尔字母用同一个`а`既表示后元音，也表示其前化变体，因此`q`模式无法区分*äkä*和*aqa*；扩展字母`ä`补上了这条规则所缺的信息（§20）。

试验场的`q`开关之所以存在，是为了让这一点可以被检验，而不只是被断言。把`q`模式用于当代新闻或社交媒体文本，不出一段，借词造成的扭曲就会出现在屏幕上。

## 9. 用`y`表示`ы`：后不圆唇元音

CTA和土耳其语把`ы`[ɯ]写作无点 **`ı`**[[8]](#ref8)。Jany-Latyn写作 **`y`**，而试验场允许二者互换。这样做会暴露两个相互叠加的问题。

第一个问题是大小写转换。无点`ı`和带点`i`是两个不同大写字母的小写形式，要正确映射它们，需要区分区域设置的大小写转换；土耳其语和阿塞拜疆语的映射在Unicode字符数据库中是一个有文档记载的特殊情况[[11]](#ref11)。土耳其语的解决办法是第二个大写字母：`ı`对应`I`，`i`对应`İ`。只有当链条中的每个系统都应用这些映射，并且读者认识这个字母时，这才成立。一个没有学过土耳其语的柯尔克孜读者没有理由知道`İ`的存在，因此一个大小写转换正确的`KIRGIZ`读起来仍然是*КИРГИЗ*：这一区别在编码中保留了下来，却在阅读中丢失了。那座湖不用全大写的例子也能说明同样的问题，因为*Ысык-Көл*写作`Isıq-Köl`，而在那些区域设置之外的任何人都会把开头的大写字母读作带点的`i`。

在`tr_TR`或`az_AZ`区域设置之外——也就是在大多数数据库、索引和运行时环境中——这一区别在编码中也会丢失，因为两个字母都坍缩为普通的`I`。于是*КЫРГЫЗ*和*КИРГИЗ*到达时就成了同一个字符串，而`kırgız`转为大写后成为`KIRGIZ`，这是吉尔吉斯斯坦已经弃用的一个他称。因此，无点配置增加了一种依赖：文本所到之处都必须有符合区域设置的大小写转换。拉丁字母`y`没有这种依赖：在任何区域设置和任何大小写函数下，`Y`和`I`都是不同的大写字母，而国家自己的英文名称——自1993年以来一直用于条约、护照和外交场合——是*Kyrgyz Republic*。

第二个问题是这一区别并不可靠。`y`和`i`在任何字号下都不会混淆，因此*kyna*和*kina*永远不会相撞。在无点`ı`下，同样这对词只差一个点，而这个点在小字号、手写和低分辨率屏幕上都会退化。在完整形式以下，它更是完全消失：简易形式和搜索折叠都把`ı`归为`i`，于是*kına*和*kina*在随意书写中成了同一个字符串，在索引中成了同一个键。用`y`，这一区别在任何地方都能保留。一旦元音再也无法承载这一区别，就必须由辅音来承载，这就是为什么试验场的`ı`模式会开启音位变体`q`。因此，采用`ı`的代价并不只是一个字母：它重新打开了§8的`q`问题。

穆萨耶夫的方案从另一个方向得出了同一个字母（§21.3），而这样做也偏离了它自己的历史基础：特内斯塔诺夫把`ы`写作`ь`，而把`y`用于`ү`[[4]](#ref4)。

## 10. 用`í`表示`й`：硬腭滑音

用不带符号的`i`同时书写`и`[i]和`й`[j]会产生条形码：*бийик* → `biiik`，*кийим* → `kiiim`，*кийин* → `kiiin`。连续三四道竖笔很难解析，也无法与长元音区分。试验场可以按需呈现这种映射（§7），因此这一论断可以在一页真实文本上评判，而不是只凭三个词。

Jany-Latyn的滑音在所有位置上都是 **`í / Í`**：*aí*、*toí*、*tyíyn*、*biíik*、*kiíim*。有四个论点支持它。

1. **单独的滑音字母是被迫的，而不是选择的**。CTA把滑音写作`y`，它之所以负担得起，是因为它把后不圆唇元音移到了无点`ı`上[[8]](#ref8)。Jany-Latyn把`y`分配给了那个元音（§9），因此这两种角色不能共用一个字母。如果共用，元音加滑音的固有序列就会坍缩：*тыйын*成为`tyyyn`，*кыйык*成为`kyyyk`，*айыл*成为`ayyl`。这与该字母本来要解决的辨读失败是同一回事，只是在左边一个元音处重新出现。

2. **选用尖音符，是因为它与`й`的关系，而不是因为它在别处的含义**。`й`是上方带一个符号的`и`；`í`是上方带一个符号的`i`。熟悉柯尔克孜语西里尔字母的读者已经把这一对视为相关而又不同的字母，而`i`/`í`把这种关系原封不动地移植过来。

3. **它保留词根**。柯尔克孜语是黏着语，词干必须保持可辨认。*Кийим*（衣服）一目了然地来自*кий-*（*kií-*，穿）；*тийиштүү*来自*тий-*（*tií-*）。把它们缩成`kiim`和`tiiştüü`，会截断动词词干，并任意地拆散相关形式：`biíi`（它的舞蹈）会保留滑音，而`biíik`（高的）却会失去它。

4. **它使滑音没有例外**。每个西里尔字母`й`在每个位置上都成为`í`，没有位置规则，也无需查表。

条形码论证只适用于完整形式。在简易形式中，`í`降为`i`，*biíik*又变回`biiik`（§19）。这是双语域设计的一项真实代价，而不是该设计能够避开的东西。

### 为什么用尖音符，而不用别的符号

简而言之：在能加在`i`上的各种符号中，尖音符最轻、可用性最广，而且在本系统内没有与之竞争的用途，因为柯尔克孜语的重音不书写，长度用双写表示。`i`是正确的基字，因为[j]是[i]的半元音对应音，也因为带符号的`i`在符号被去掉时退回`i`，而不是`y`。唯一真正的冲突是与教学材料中的重音符号冲突，而这一冲突范围很窄，并且有比更改滑音更好的解决办法。

论点2留下了一个尚未消除的反对意见。尖音符在别处另有联想：在捷克语、斯洛伐克语、匈牙利语和爱尔兰语中标记长度，在西班牙语中标记重音，而正是一种外来的联想在§12.1中排除了长音符。区别在于*柯尔克孜*读者带到页面上的是什么。柯尔克孜语的重音是有规律的，从不书写，长度用双写表示，因此在本系统内，尖音符没有与之竞争的用途；而长音符的通常取值——长度——在柯尔克孜语中是一个活跃的范畴。

这一选择里藏着两个问题，最好把它们分开来看：用哪个符号，以及它加在哪个字母上。

在能加在`i`上的符号中，分音符（`ï`）在视觉上会与`ö`和`ü`上表示前化的符号相撞。扬抑符（`î`）可用，但在土耳其语中它标记阿拉伯语借词中的长度（*millî*、*tarihî*），而这正是排除长音符的那个反对理由，只不过来自距离最近的拉丁字母突厥语传统。抑扬符（`ǐ`）在正文字号下更重，并且在Latin-1之外。有两个替代方案足够接近，值得作为试验场选项提供，而不是直接否定（§7）。短音符`ĭ`的理由最充分：它是那个西里尔字母的字面对应，后者正是加了短音符的`и`，而ALA-LC正是出于这个原因选择了它[[8]](#ref8)。它输在重量和普及度上：在阅读字号下比尖音符更重，在Latin-1之外，大多数键盘布局和长按菜单中都没有它；而这些都是程度上的差别，因此试验场用它呈现整篇文本，让比较在一页纸上进行。波浪符`ĩ`还要更弱，而且带有一种相互作用：同时为软腭鼻音选择`ñ`的读者，会把同一个符号加在两个承担无关作用的字母上，试验场对此会发出警告。`í`（U+00ED）是这组中最轻的，它在Latin-1中，在西班牙语、葡萄牙语、爱尔兰语和冰岛语键盘布局上，也在标准的移动设备长按菜单中。

基字是另一个问题，§21.1中比较的各系统对此有四种回答：ISO 9和特内斯塔诺夫1928年的字母表用`j`，BGN/PCGN和CTA用`y`，土库曼语用`ý`[[20]](#ref20)，ALA-LC用带符号的`i`。选`j`和选`y`，都是把这个音映射到在某种拉丁书写传统中已经表示/j/的字母上：`j`来自德语和斯拉夫语的拼写，`y`来自英语和土耳其语的拼写。土库曼语是富有启发性的例子，因为它的出发点与本正字法相同：它没有无点`ı`，所以`y`表示后不圆唇元音[ɯ]，滑音写作`ý`，一个音节可以同时带有二者，如*ýyl*（年）。

有两点支持以`i`而非`y`为基字，而且二者都不依赖于西里尔字母是源文字。第一点是，[j]是[i]的半元音对应音，即同样的发音，只是不自成音节；这就是为什么标音可以把它写成非音节性的`i`，也是为什么*ko-i-on*和*ty-i-yn*说得足够快时，就成了*koíon*和*tyíyn*。滑音无论出现在哪里都保持这种身份，包括在`o`和`y`之后。[ɯ]的半元音对应音不是[j]，而是[ɰ]，一个柯尔克孜语用不上的软腭近音，因此`ý`会断言一种语音事实所否认的亲缘关系。西里尔字母恰好与此一致，因为`й`是带符号的`и`，并在同一些词根中与`и`交替（*кий-*、*кийим*）。

第二点是符号脱落时会发生什么。简易形式和搜索折叠都去掉附加符号，所以`í`降为`i`，而`ý`会降为`y`。在`í`之下，*тыйын*和*айыл*到达ASCII时是`tyiyn`和`aiyl`。在`ý`之下，它们会成为`tyyyn`和`ayyl`，也就是论点1为防止它而引入单独滑音字母的那种坍缩，从后门又回来了。排序又增加了第三点考虑：按照§17.1的排序原则，带符号的`y`会在字母表末尾被教授和归档，远离与它交替的那个字母。

唯一真正的冲突在于重音标记法。教学材料、词典和外语教科书用尖音符标记重读音节（*a-tá*、*o-ro-mó*），而在`i`上，这个符号与滑音会是同一个字符。这一冲突比初看起来要窄：它只在重音落在/i/上时才出现，其他每个元音都仍然可以毫无歧义地加上表示重音的尖音符；而且柯尔克孜语的重音大体可以预测，并落在词末，因此标记重音只是在少量专门材料中处理例外和借词的手段，而不是普通文本的特征。按频率衡量，滑音在连续文本中不断出现，重音符号则不然。解决办法是给教学提供一种不与任何字母竞争的手段：把重读音节加粗，或在其前加国际音标重音符号（*bi-ˈíik*），后者还有一个额外的好处，就是在整个元音系统中用法完全一致。§23.6把这一约定列为尚待撰写的工作。

哈萨克斯坦2018年的字母表是一个警示性的例子（§21.5），而它的教训并不是尖音符行不通：分散在六七个字母上的尖音符读起来显得杂乱，而单一的、系统性的用法则不会。`í`是一个字母，只有一种用途。

## 11. 用`j`表示`ж`：浊塞擦音

固有词中位于词首和词中的`ж`是浊龈后塞擦音[dʒ]，即英语*journey*中*j*的音，而不是`zh`所暗示的、经由俄语传入的擦音[ʒ]。Jany-Latyn写作 **`j`**：*jakşy*、*jaŋy*、*jol*、*jigit*。

对柯尔克孜语来说，这并不是一个新奇的选择。BGN/PCGN罗马化——吉尔吉斯斯坦政府采用它以拉丁字母书写地理名称[[8]](#ref8)——同样把`ж`写作`j`，其结果可以在吉尔吉斯斯坦护照上和国际报道中看到：*Japarov*、*Jalal-Abad*。相比之下，`zh`在该语言使用频率最高的辅音之一上多花一次击键，而且向国际读者传达了错误的信息。

与CTA的分歧——CTA把`c`分配给这个音，把`j`分配给[ʒ][[8]](#ref8)——是有意为之的，论证见下文。

**`j`用在CTA用`c`的地方**。在CTA中，按照土耳其语的做法，`c`是[dʒ]，`j`是借词中的[ʒ]。Jany-Latyn要安置的是一个字母而不是两个，因为柯尔克孜语西里尔字母用单一的`ж`表示这两个音，而它把这个字母安置在`j`上。对于没有土耳其语读写能力的读者来说，`c`不是一个中性的符号：它使受法语影响的读者联想到[s]，使英语读者联想到[k]。几乎每一个没有受过土耳其语训练、能读拉丁字母的读者，都会把`j`读成接近[dʒ]的音，而且它已经是柯尔克孜语官方罗马化中用来表示`ж`的字母。对于一个面向在非土耳其语键盘上打字的侨民、并着眼于国际辨读的系统来说，`c`是一个假朋友。

这一拆分还带有§8的词表依赖：CTA把固有词*жазуу*写作*cazuu*，把借词*журнал*写作*jurnal*，而柯尔克孜语西里尔字母对二者都写同一个`ж`。加上`q`和`ğ`，对齐CTA的设置在其辅音中有三处需要借词表，而单一的`j`、`k`和`g`一处也不需要。

这也是对柯尔克孜语拉丁字母传统的偏离，而不只是对一个现代委员会的偏离。特内斯塔诺夫的字母表用`j`表示滑音`й`，用`c`表示塞擦音`ж`（在1938年的修订中被`ƶ`取代）[[4]](#ref4)，与CTA和穆萨耶夫的分配相同。本正字法接受这一断裂：`ƶ`读起来像一个经过修改的`z`，在表示[dʒ]上并不比`c`好，而且它仍是一个字体支持很薄弱的罕见Latin Extended-B字符。

## 12. `ö`和`ü`：前圆唇元音

### 12.1 用`ü`表示`ү`，以及替代方案

Jany-Latyn表示 **`ү`**[y]的字母是 **`ü / Ü`**，与土耳其语、阿塞拜疆语和土库曼语中同一元音的用法一致，也与2021年的哈萨克语拉丁字母表一致，后者同样为哈萨克语的`ү`选择了带变音符的ü[[5]](#ref5)。长度通过双写另行处理：*kün*（天）中是短的`ü`，*küü*（乐曲）中是长的`üü`。

这些替代方案是成对出现的，而不是相互独立的。试验场为前圆唇元音提供四种配置，其中三种是用不同字形进行的同一个实验：

| 配置 | `ө` | `ү` |
| :--- | :---: | :---: |
| 拉丁变音符（Jany-Latyn） | `ö` | `ü` |
| 混合`ө` | `ө` | `ü` |
| 西里尔字母`ұ` | `ө` | `ұ` |
| 长音符`ū` | `ө` | `ū` |

这种成对关系对解读结果很重要。`ü`的每一种替代方案都与西里尔字母`ө`搭配提供，因此选择`ұ`或`ū`并不是用一个字母换另一个字母：它还接受了§12.2所述的文字混用代价。这些代价是相互叠加的，而不是并列存在的，*kөrūū*与*körüü*的对比就是这种叠加在页面上的样子。

长音符`ū`经过测试后被搁置。在拉脱维亚语和毛利语中，长音符标记元音的*长度*，而长度正是读者最可能赋予它的取值。柯尔克孜语有音位性的长度，因此用`ū`表示一个元音的*音质*，就给柯尔克孜读者提供了一种现成而错误的读法。内部冲突是决定性的：本系统中的长度用双写表示，因此`ū`的长形式会是`ūū`，读起来像是把长度标记了两次。这一论证是针对柯尔克孜语的，而不是普遍的：2021年的哈萨克字母表用带长音符的ū表示哈萨克语的`ұ`[[5]](#ref5)，这在那里行得通，因为哈萨克语没有同样的长度对立。

哈萨克语的`ұ`被保留为一个过渡性的显示选项，因为在文字规划的讨论中，与西里尔字母相近的字形常被提出来，作为西里尔字母读者的过渡桥梁。它带来两个问题。它那窄小的横杠正是区别它的特征，而横杠恰恰是在小字号下和激进的抗锯齿处理下最先退化的部分，到那时它就接近拉丁字母`y`，而这个字母在这里已经承担着自己的音位负担。而且，`ü`能干净地降为ASCII字母`u`，`ұ`则不同，它根本没有ASCII备用形式，因此它恰恰在简易形式为之而存在的那些环境中失效。

### 12.2 用`ö`表示`ө`，以及文字混用的代价

Jany-Latyn表示 **`ө`**[œ]的字母是 **`ö / Ö`**。西里尔字母`ө`在试验场中作为过渡和教学材料的显示模式保留，而不是作为Jany-Latyn的候选。

作者认为行内的西里尔字母`ө`完全可以辨读，正因为如此，反对它的理由不能建立在辨读性上。在其余都是拉丁字母的文本中保留一个西里尔字母，会带来三项代价，而无论读者觉得这个字形多么易读，这三项代价都成立：

- **字形度量**。不支持西里尔字母的字体会为这一个字形换用另一种字体；支持西里尔字母的字体仍把其拉丁字母和西里尔字母作为不同的设计来绘制，因此`ө`的x字高通常比旁边的拉丁小写字母小。无论哪种情况，这个词里都带着一个与其所在行不匹配的字母，而且其效果会随着文本经过的每一个字体栈而变化。这是三项代价中最不带推测性的一项，也最容易检验（§23.4）。
- **排序**。在Unicode排序算法下，拉丁字母和西里尔字母分属不同的权重组[[6]](#ref6)，因此混合字符串与纯拉丁字母字符串相比，排序结果难以预测。为一份名单按字母排序，会以一种本不必要的方式依赖于区域设置。
- **分词（预测，未经测量）**。SentencePiece默认在Unicode文字边界处切分输入，因此`kөl`可能被切成三段而不是一段[[7]](#ref7)。如果字节级BPE分词器的预分词器不分文字地把所有字母归为一组，就不一定会这样，而且`ö`和`ө`在UTF-8中都同样占两个字节，所以效果取决于分词器。§23.1说明了如何检验。

标准的`ö`避免了全部三项代价，而对读者的要求并不比`ü`已经提出的要求更多。

## 13. `ç`和`ş`：咝音

Jany-Latyn的咝音是 **`ç`** 和 **`ş`**：*çaí*、*şaar*。二合字母曾被考虑过，但在完整形式中被搁置了，因为柯尔克孜语的形态会使它们产生冲突。

施事后缀`-чы/-чи`加在以`ш`结尾的词干上，是日常的例子：*баш* + *-чы* → *башчы*，在二合字母下得到模糊了语素边界的`bashchy`，而用下加符则是清楚的`başçy`。人名中的`s`+`h`序列是另一个例子：**Исхак**（Is-hak）经由二合字母转写为`ishak`，而这也正是*ишак*会得出的写法；这是俄语和乌兹别克语中表示“驴”的词，大多数柯尔克孜语使用者都认得，尽管固有词是*эшек*。下加符把二者分开：`ishak`对`işak`。

俄语的`щ`并入 **`ş`**（*ящик → íaşik*、*борщ → borş*），而不产生三合字母。柯尔克孜口语把它实现为[ʃ]，而`şç`在反向转换时会与固有的`başçy`相撞。

二合字母并没有被抛弃，而是被重新安置了。反向转换器接受旧式的`ch`、`sh`和`sch`，使较早的文本和随意书写能够正确转换，而试验场可以用二合字母模式呈现整篇文本以供比较。

## 14. 用`ŋ`表示`ң`：软腭鼻音

**`ŋ / Ŋ`**（U+014B / U+014A）标记单一音位[ŋ]，并使它与真正的`n`+`g`辅音丛保持区别：*күнгө*（词干*kün* + 与格 *-gö*）仍为`küngö`，而*жаңы*是`jaŋy`，不是有歧义的`jangy`。

选用eng是为了字形的连续性。西里尔字母`ң`（带下伸部的en）和特内斯塔诺夫1928年的拉丁字母`ꞑ`（带下伸部的n）[[4]](#ref4)都把`n`延伸到基线以下，而`ŋ`（eng）把右腿弯成钩，效果相同。在现有的选项中，它是唯一一个在西里尔字母和1928年拉丁字母两种传统中都有连续性的字母。CTA的`ñ`（带波浪符的n）则把符号放在字母上方，而且对于接触过任何西班牙语的读者来说，它带有一种特定的错误读法，即*piñata*和*mañana*中的[ɲ]。

`ŋ`也有实实在在的代价：

- 在移动设备上的可用性参差不齐。在美国区域设置下的安卓键盘上，可以通过长按`n`输入它；iOS和非美国区域设置尚未核查，而`ñ`是在任何地方都可靠存在的选项。
- 大写`Ŋ`有两种不同的设计在流通，一种是放大的小写形式，一种是以N为基础的形式，因此全大写文本在不同字体间可能显得不一致。
- 它在Latin-1和Windows-1252之外，而`ñ`在其中。

土库曼语曾把这个音写作`ꞑ`、`ñ`和`ng`，最后才定为`ň`，用的是抑扬符而不是波浪符[[20]](#ref20)；哈萨克斯坦在2021年之内从`Ŋ`改为`Ñ`，而乌兹别克语草案保留二合字母`ng`[[9]](#ref9)。这个问题在整个语族中都悬而未决。Jany-Latyn基于推导和假朋友两方面的论证保留`ŋ`，并在试验场中把`ñ`作为对照设置，提供给更看重移动设备输入的人。键盘布局（附录D）使`ŋ`在桌面上只需一次击键，而简易形式把它写作`n`（*jaŋy → jany*），这正是人们已经在键入的。

## 15. 元音、长度与`е`

柯尔克孜语有八个基本元音，按前/后和圆唇/不圆唇和谐组织：

| 舌位高度 | 前不圆唇 | 前圆唇 | 后不圆唇 | 后圆唇 |
| :--- | :---: | :---: | :---: | :---: |
| **高** | **i**（и） | **ü**（ү） | **y**（ы） | **u**（у） |
| **中** | **e**（э, е） | **ö**（ө） | — | **o**（о） |
| **低** | — | — | **a**（а） | — |

其中六个有长短对立：`аа`、`ээ`、`оо`、`өө`、`уу`、`үү`。两个高不圆唇元音`ы`和`и`没有相应的长元音[[4]](#ref4)。长度一律用双写表示。

其拉丁字母需要作出决定的元音，在§9（`y`）和§12（`ö`和`ü`）中论证，滑音在§10中论证；长度和`е`在下文讨论。

### 15.1 音位长度，以及`е`问题

长度用**双写**表示：*ток*[tok]（饱的）对*тоок*（鸡），*Ala-Too*、*aalam*、*jeek*、*kuu*、*küü*。

另一种方案是在单个元音上加长音符，即拉脱维亚语和毛利语的模式，那样*took*（тоок，“鸡”）会写成*tōk*，*Ala-Too*会写成*Ala-Tō*。它是两种标记法中更紧凑的一种，也是这些正字法的读者会预期的写法。之所以更倾向于双写，有四个理由：组合符号会被搜索层和数据库层不一致地去除或规范化；双写不需要死键或长按，只需把同一个键按两次；柯尔克孜语西里尔字母已经用双写表示长度，柯尔克孜语阿拉伯字母正字法也是如此[[4]](#ref4)，因此这一约定是继承的而不是发明的；而且会延长的六个元音中有两个已经带有符号，因此长的`öö`和`üü`将需要叠加符号的`ȫ`和`ǖ`，它们在Latin-1之外，字体支持薄弱，不用死键就无法键入。

柯尔克孜语的长元音有时被描述为一种古旧遗存，但它们大体上是由元音间辅音脱落而产生的次生发展（*тоо*来自一个带软腭音的较古形式），而不是土库曼语所保留的那种原始突厥语长度[[26]](#ref26)。无论如何，这一对立在现代柯尔克孜语中是活跃的，而这就是正字法所需要的全部。

唯一必须明确解决的不规则之处是`е`。柯尔克孜语西里尔字母从不双写它；长的/eː/在所有位置上都写作`ээ`（*ээги*、*керээз*、*кээде*、*жээк*），Jany-Latyn照其字面写作 **`ee`**（*eegi*、*kereez*、*keede*、*jeek*）。但`е`在俄语借词中还有第二个作用，即在词首（*Европа*、*Енисей*）和元音后（*переезд*、*проект*）表示[je]。Jany-Latyn用它已有的滑音字母来处理：借词中的[je]写作 **`íe`**（*Íevropa*、*pereíezd*、*proíekt*），固有词词首的[e]仍为 **`e`**（*ene*、*el*），辅音后的[e]也仍为 **`e`**（*kel*、*mektep*）。在柯尔克孜语口语中不发生j化的借词里，元音后的`э`按普通写法书写，如*поэт*和*аэропорт*：*poet*、*aeroport*。三个字素（`e`、`ee`和`íe`）覆盖了所有位置。它们在转换回西里尔字母时如何处理，在§18.1中规定。

## 16. 借词符号`ъ`和`ь`，以及`я`、`ё`、`ю`

硬音符号和软音符号标记元音间隙和腭化，而Jany-Latyn用它已有的滑音来体现这些。j化元音之前的分隔符号被吸收进`í`（*объект → obíekt*、*семья → semía*、*разъезд → razíezd*）。音节尾的软音符号——柯尔克孜语音系在自然言语中并不把它实现为腭化——被删去（*июль → iíul*、*апрель → aprel*、*роль → rol*）。j化元音一律分解：**я → ía**、**ё → ío**、**ю → íu**（*saíakat*、*koíon*、*aíuu*），而非j化的元音间隙则保持普通写法（*диаграмма → diagramma*）。

结果是，用Jany-Latyn书写的每个词都是一个与`\p{L}+`匹配的连续字母串，内部没有撇号。这一性质有具体的后果：搜索索引和朴素的分词器不会在标点处把词断开，双击可以选中整个词[[10]](#ref10)。乌兹别克语在`oʻ`和`gʻ`中使用撇号，它现实地展示了另一种做法在实践中的代价，因为这个符号经常被键盘产生的任何一种引号字符所替代。

然而，这一性质**并不**能使URL成为纯ASCII。`í`、`ŋ`、`ö`、`ü`、`ç`和`ş`都是非ASCII字符，在URL路径中会被百分号编码（`ŋ`变成`%C5%8B`）。`\p{L}+`性质所提供的是一个单一、不断开的词元；产生干净slug的是简易形式（§19），它是生成slug的正确层面：*jaŋylyktar → janylyktar*。

## 17. 字母顺序

本节说明Jany-Latyn的字母顺序，即读者学习的顺序；§17.4展示它在排序中改变了什么，附录C给出软件所需的规则。

### 17.1 排列原则

大部分顺序由一个问题决定：经修饰的字母放在哪里。柯尔克孜语西里尔字母和拉丁字母突厥语正字法对此的回答相同：把它紧接在被修饰的字母之后，而不是放在字母表末尾。柯尔克孜语西里尔字母把`ң`放在`н`之后，`ө`放在`о`之后，`ү`放在`у`之后；土耳其语和阿塞拜疆语把`ç`放在`c`之后，`ş`放在`s`之后，`ö`和`ü`放在`o`和`u`之后。Jany-Latyn同时遵循这两者。

### 17.2 Jany-Latyn字母表（28个字母）

**A B Ç D E F G H I Í J K L M N Ŋ O Ö P R S Ş T U Ü V Y Z**

**a b ç d e f g h i í j k l m n ŋ o ö p r s ş t u ü v y z**

这一原则的三个结果在其中清晰可见。`Í`紧随`I`，与西里尔字母读者已经熟悉的`и`/`й`相邻关系相呼应。`Ŋ`紧随`N`，正如`ң`紧随`н`。`Y`位于其在拉丁字母表中靠近末尾的位置，而不是`ы`在西里尔字母表中的位置，这符合国际上对这个字母形状的预期。

通用突厥语字母遵循同一原则。它的34个字母的顺序把`Ğ`放在`G`之后，`X`放在`H`之后，`Ñ`放在`N`之后，`Ö`放在`O`之后，`Ū`和`Ü`放在`U`之后，`Ə`放在`E`之后，`Q`紧接在`K`之后[[17]](#ref17)，每个字母都放在与之配对的字母旁边，而不是放在末尾或沿用传统的拉丁字母顺序。下面的`q`各行出于同样的理由把`Q`放在`K`之后。

`C`、`Q`、`W`和`X`不在字母表之内。Jany-Latyn从不生成它们：`ч`是`ç`，`ц`是`ts`，其余的属于其他配置或外语拼写。

### 17.3 各字母表并列对照

| 配置 | 字母数 | 字母表 |
| :--- | :---: | :--- |
| Jany-Latyn | 28 | Aa Bb Çç Dd Ee Ff Gg Hh Ii Íí Jj Kk Ll Mm Nn Ŋŋ Oo Öö Pp Rr Ss Şş Tt Uu Üü Vv Yy Zz |
| q+ğ（§8） | 30 | Aa Bb Çç Dd Ee Ff Gg Ğğ Hh Ii Íí Jj Kk Qq Ll Mm Nn Ŋŋ Oo Öö Pp Rr Ss Şş Tt Uu Üü Vv Yy Zz |
| q+ğ+ı | 30 | Aa Bb Çç Dd Ee Ff Gg Ğğ Hh Iı İi Jj Kk Qq Ll Mm Nn Ŋŋ Oo Öö Pp Rr Ss Şş Tt Uu Üü Vv Yy Zz |
| 对齐CTA（q+ğ+ı+c+ñ） | 31 | Aa Bb Cc Çç Dd Ee Ff Gg Ğğ Hh Iı İi Jj Kk Qq Ll Mm Nn Ññ Oo Öö Pp Rr Ss Şş Tt Uu Üü Vv Yy Zz |
| 通用突厥语字母，供参照 | 34 | Aa Bb Cc Çç Dd Ee Əə Ff Gg Ğğ Hh Xx Iı İi Jj Kk Qq Ll Mm Nn Ññ Oo Öö Pp Rr Ss Şş Tt Uu Ūū Üü Vv Yy Zz |

各字母表以大小写成对的形式给出，因为这些字母对各不相同：在最后三行中，`I`是无点`ı`的大写，带点的`i`取`İ`为大写。

在q+ğ+ı一行中，把`ы`写作`ı`就空出了`y`，滑音便取用了它：§10中支持`í`的论证是`y`另有他用，而在这里它没有。`Y`回到它在末尾的普通拉丁字母位置。同时保留`í`也是可以的，试验场也提供这一选项，代价是字母表中会有`I`、`İ`和`Í`三个只靠上方符号区分的字母。

最后一行就是巴库字母表本身[[17]](#ref17)，以便对照阅读其他各行。它上面一行是柯尔克孜语改编版会采用的字母表：同一字母表去掉`Ə`、`Ū`和`X`，理由见§21.2。二者都没有`W`。

### 17.4 排序：定制改变了什么

字母顺序必须以*定制*的形式交给软件：即对默认Unicode排序顺序的一小组调整[[6]](#ref6)，而默认顺序对柯尔克孜语一无所知，会把`ç`归为`c`的变体。附录C给出了这组调整；本节则为永远不会去看其语法的读者展示它改变了什么。

| Jany-Latyn顺序 | q+ğ+ı顺序 | 变动 |
| :--- | :--- | :--- |
| bas, baş, bat | bas, baş, bat | 不变：两者中`ş`都在`s`之后 |
| kene, keŋ, kep | kene, keŋ, kep | 不变：两者中`ŋ`都在`n`之后 |
| kol, konok, köl, köp | kol, konok, köl, köp | 不变：两者中`ö`都在`o`之后 |
| kul, kum, kül, küü | kul, kum, kül, küü | 不变：两者中`ü`都在`u`之后 |
| kir, kyz | kız, kir | 颠倒：`ı`按土耳其语方式排在`i`*之前*，因此每个含高后不圆唇元音的词都移到其带点`i`的相邻词前面 |

其中两行包含一个读者常常觉得违反直觉的结果。由于`ö`和`ü`被算作独立的字母，而不是`o`和`u`的带符号形式，所以在该位置上带基本元音的*每一个*词，都排在带修饰元音的*每一个*词之前：*köl*排在*konok*之后，而不是紧挨着*kol*。西里尔字母顺序对`о`/`ө`和`у`/`ү`早已如此，因此柯尔克孜读者觉得它很熟悉，而搜索功能的实现者往往不然。

最后一行是q+ğ+ı设置对维护词典或索引的人来说的实际代价：它改变的不是一个字母的位置，而是把含有该语言最常用元音的每个词条重新洗牌。

表外还有两种更大的变动，因为该表比较的是拉丁字母各配置，而不是拉丁字母与西里尔字母。由于`ç`以`c`为锚点，*Чычкан*从西里尔字母表的第28个字母移到拉丁字母表的第3个字母，因此一份人名索引在转换时不只是位移，而是重新分节。首字母变成多字符字素的词则会彻底改变所在的节：*Екатеринбург*归在`Íekaterinburg`之下，即在`Í`下，远离其他所有`E`条目。

## 18. 转换回西里尔字母

西里尔字母→拉丁字母的转换是确定性的、基于规则的：每一个Jany-Latyn形式都由位置和元音环境计算得出，不用词表。拉丁字母→西里尔字母的转换同样是确定性的，它能准确还原柯尔克孜语固有词汇，但对借词来说它**并非无损**。西里尔字母→拉丁字母的映射是多对一的，因为若干仅存在于俄语借词中的西里尔字母区别被有意合并了，而被合并的区别无法恢复。

§18.1和§18.2是写给评判这一正字法的人看的：转换器如何处理借词，以及为什么。实现必须复现的内容在附录A—C中规定，字母顺序在§17中规定。

### 18.1 固有词优先规则

> **当两个西里尔字母拼写映射到同一个拉丁字母串时，反向转换还原在柯尔克孜语固有词汇中出现的那一个。只存在于俄语借词中的区别，才是允许丢失的区别。**

这一条规则决定了每一种有歧义的情况，而它源自原则1：必须在自动转换中保全下来的语料库，是柯尔克孜语的语料库。

表中出现哪些损失，部分取决于§23.6留而未决的一个问题：借词是按其俄语来源拼写，还是按柯尔克孜语发音拼写。*poet → поет*、*aeroport → аеропорт*，在目前的近似处理下属于损失，而在忠实于来源的处理下则不会是损失。

| 拉丁字母 | 还原为 | 原因 | 损失了什么 |
| :--- | :---: | :--- | :--- |
| `ts` | **тс** | 固有词中的т+с频繁而能产：*кетсе*、*айтса*、*өтсө* | 借词中的`ц`：*tsirk → тсирк* |
| 元音后的`íe` | **йе** | 词根完整性：*kií-* → *кийет*、*tií-* → *тийет* | 借词中元音后的`е`：*proíekt → пройект*；以 *-аев*、*-иев*结尾的姓：*Musaíev → Мусайев*；另外，*tiíeşelüü → тийешелүү*，它保留了词根*тий-*，而公认的拼写是*тиешелүү* |
| 词首的`íe` | **е** | 没有固有词以йе开头 | — |
| `ío` | **ё** | 柯尔克孜语已把固有的йо拼作`ё`：*коён* | 借词中的`йо`：*raíon → раён* |
| `ía` | **я** | 柯尔克孜语固有词中没有单纯的`и`+`а`元音间隙，因此这一序列在任何位置都没有歧义 | 借词中的`ья`：*semía → семя* |
| 元音后的`i` | **й** | 完整形式把й写作`í`，但简易形式（§19）和试验场的`i`滑音把它写作`i`，而固有的ай、ой、үй远多于元音后带и的借词：*bai → бай*、*tooi → тоой* | 借词中元音后的`и`：*ukrain → украйн*、*arhaizm → архайзм* |
| `ş` | **ш** | 对固有词汇而言是1:1 | 借词中的`щ`：*borş → борш* |
| 旧式的`sh` | **ш** | 固有的ш很常见；固有的с+х不出现 | 二合字母模式下的人名*Ishak* |
| 元音后的`e` | **е** | 近似处理；柯尔克孜语在这一位置没有固有的э | 借词中的`э`：*poet → поет* |
| 被删去的`ь`、`ъ` | *（无）* | 无法恢复 | *aprel → апрел* |

只有`ts`、元音后的`íe`和旧式的`sh`涉及固有文本；其他各行只决定丢失哪一种借词拼写。`ts`最为重要，因为条件式把`т`+`с`放在每个以`т`结尾的词干的语素边界上，所以把`ts`送回`ц`会损坏一个开放类别的固有词形。

### 18.2 可选的借词还原表

丢失借词拼写对于语料库工作是可以接受的，而对于比如说转换一份法律文本则不可接受。因此，参考引擎附带一份小型的、有明确文档说明的**借词还原表**：即那些西里尔字母形式无法按规则推导的已知借词（*semía → семья*、*statía → статья*、*Ishak → Исхак*，以及类似的词），叠加在基于规则的核心之上，并且可以开关。

这份表是一个查找表，而对这一架构所作的论断比“任何地方都没有词典”要窄：核心本身是完整的、无需词典的，而这份表只会还原核心已经标记为有损的借词拼写。它从不影响固有词汇，也从不改变西里尔字母→拉丁字母的输出。

这份表本身也带来一种不对称：把*ishak*还原为*Исхак*的旁路，在二合字母模式下会把俄语借词*ишак*弄错。这一取舍是有意的，因为文件中出现的是人名。

同一条规则也决定了这份表在哪里止步。*Асхат*转换为`Ashat`，转换回来时成了*Ашат*，任何条目都无法修复它：在二合字母输入中，`ashat`也是固有词*ашат*，而§18.1会优先还原它。*Исхак*之所以可以收入，是因为它所取代的词*ишак*是借来的。这份表可以收入一个其竞争者是借词的名字，而不能收入一个其竞争者是柯尔克孜语词的名字；这一界限比“例外表都有代价”这种一般性的谨慎更为坚实。

## 19. 两种语域：完整形式与简易形式

Jany-Latyn一并定义两种语域，而不是定义一种文字再附加一个权宜之计。

**完整形式**——`ö`、`ü`、`í`、`ŋ`、`ç`、`ş`——是完备的形式：用于印刷品、词典、官方文本、试验场的默认输出，以及任何把该正字法作为其本身来呈现的场合。

**简易形式**是ASCII，供未经改装的键盘使用：

`ö → o`、`ü → u`、`í → i`、`ŋ → n`、`ç → c`、`ş → s`

每个字母去掉其附加符号，此外什么都不变。*Çaí*变成`cai`，*şaar*变成`saar`，*jaŋy*变成`jany`，*biíik*变成`biiik`。

主张改用另一种映射——`ç → ch`、`ş → sh`——的理由是真实存在的：二合字母能更好地向读者提示读音，而且它们是人们今天在键入的写法（*chai*、*jakshy*）。在这里有两点考虑压过了它。第一是一致性：如果其他每个字母都去掉一个符号，咝音也应如此，这样简易形式就会教人认识完整形式的形状，而不是与之竞争：键入`cai`的读者离`çaí`只差附加符号，而键入`chai`的读者拼的是另一种词形。第二是折叠：标准的去重音处理本来就会这样映射：`ç→c`、`ş→s`，因此采用这一映射，简易形式*就是*折叠形式，搜索折叠几乎不费成本（附录B）。若用二合字母，两种形式会折叠成不同的键，每个索引都需要定制处理。

二合字母备用形式是过渡性的，而不是第二种内部体例；本项目自己的早期草案曾以`ch`/`sh`为参考。发展方向是去除符号的映射：已经内化了`ç`的读者会把*çöírö*随手写成*coiro*，并把它读作同一个词。

代价是合并。把`ş`去掉符号成为`s`会使它与固有的`s`合并：*баш*和*бас*都成为`bas`，*аш*和*ас*都成为`as`。二合字母备用形式避免了这种合并，但重新引入了`sh` ≈ с+х的冲突，并使词变长。这是一个真正的取舍，因此试验场实现了**两种**备用形式，让读者在真实文本上比较。解决它的正确方法，是统计每种映射在一个语料库中合并了多少个不同的词（§23.3）。

简易形式本来就有合并，而且一向如此：`кол`（手）和`көл`（湖）都表现为`kol`；`жаңы`（新的）和`жаны`（他的灵魂）都表现为`jany`。这与柯尔克孜语使用者早已采用的发短信方式一致，而它解决歧义的方式，也正是非正式书写一贯解决歧义的方式：依靠语境，实时解决。

简易形式的两个性质限制了能在它之上构建什么：

- **简易形式是单向的**。`biiik`无法被机械地还原为`biíik`，`cai`也无法还原为`çaí`或`чай`。ASCII文本是终点，而不是中间形式。转换工具应当尽力而为地接受它作为输入，而不应声称可以往返转换。
- **它是对当前习惯的偏离，而不是对它的描述**。`ö→o`、`ü→u`、`í→i`、`ŋ→n`，与人们现在的键入方式一致。`ç→c`、`ş→s`，则不然；*chai*和*jakshy*才是现行的形式。这一映射是把习惯拉向完整形式的一种尝试，它是一个规范性的选择，不应被当作描述性的选择来呈现。

## 20. 待评估字母：`ä`、`x`、`w`

柯尔克孜语言语中可以听到三种语音区别，而柯尔克孜语西里尔字母并不书写它们。拉丁字母对这三者都有字母，而且键入起来很便宜，但它们的分量并不相同：`ä`有理由获得永久地位，而`x`和`w`——如下文所论——则没有。试验场把它们作为一个评估组提供，默认关闭。

| 字母对 | 区别 | 出现于 |
| :--- | :--- | :--- |
| `a` / `ä` | 后/ɑ/对前/æ/ | 南部言语（*äkä*、*källä*）；在标准柯尔克孜语中也经由波斯语借词和逆同化出现 |
| `h` / `x` | 喉音[h]对软腭音[x] | 借词，其实现因说话人、地区和来源而异（*haram*、*halal*、*Buhara*） |
| `v` / `w` | 唇齿音[v]对[w] | 借词，以及/b/在元音间的实现 |

这三者都不能由西里尔字母推导。柯尔克孜语西里尔字母只写一个`а`、一个`х`和一个`в`，因此转换器若不知道哪些词是借词，就无法从源文本生成`ä`、`x`或`w`。因此，它们是**直写模式字母**：在人直接书写拉丁字母时可用，自动转换永远不会生成它们。反向转换器接受它们作为输入，并把每一个折叠回基本字母（`ä → а`、`x → х`、`w → в`），这是§18.1的固有词优先规则在一种新情况下的应用：这一区别在拉丁字母中得以保留，而在转换回去时丢失，正如借词的`ц`和`щ`一样。搜索折叠以同样的方式把它们统一起来，因此丢失的区别不会使索引碎片化。

`ä`是做音系工作的那一个。另外两个只是细化借词的拼写。`ä`标记和谐类别，而和谐类别正是`q`规则所读取的：*äkä*、*ükä*和*källä*是前和谐的，取软腭音[k]，而*aqa*和*qalla*是后和谐的，取小舌音[q]。没有`ä`，规则就无法区分它们；有了它，规则就有了所需的信息。实验由此直接得出：把南部文本用`q`模式处理，先不带、再带上`ä`，测量第二种配置是否更准确。

`x`的理由与`w`一样弱，而且原因更基本：它要书写的差别并不是词与词之间的对立。说话人在*haram*、*halal*或*Buhara*中用哪一个擦音，取决于说话的是谁、在哪里说，而不取决于词，因此没有任何一对柯尔克孜语词靠[h]与[x]来区分。带有这些音的借词经由不同途径来自阿拉伯语、波斯语、察合台语和俄语，而柯尔克孜语在吸收每一个词时都重塑了源语的辅音。有时它把这个辅音丢掉，如*маала*（也作*маале*）来自*mahalla*。有时它把它变成软腭音，如*махабат*来自*muhabbat*。有时它把它硬化为塞音`к`，如*Ыктыяр*对*Ихтияр*、*Ыскак*对*Исхак*、*Аскат*对*Асхат*。这些词和名字大多以不止一种形式通行，而拼写规则不该在其中作出选择。它也不需要选择：凡是擦音保留下来的地方，Jany-Latyn的`h`都把它写出来，不管说话人怎么发音，正如西里尔字母`х`86年来所做的那样；凡是它变成`к`或消失了的地方，就没有什么需要标记的了。

`x`还带有另外两个字母所没有的一种代价。在任何一种拉丁文本中，`x`都已经有一个无处不在的国际读音（*Linux*、*LAX*、*X Factor*、*taxi*），柯尔克孜读者经常遇到这些字符串。把`x`用于软腭擦音，会使一个字母有两种没有任何规则能区分的读法，并把搜索折叠也一并拖累。所以，这一拆分标记的是柯尔克孜语使用者并不用来区分词的差别，而且耗费了一个其国际读音值得保留的字母。试验场把`x`留在评估组里，是为了能在真实文本上试用它，而不是因为这个问题仍然悬而未决。

`w`以同样的方式失败，因为元音间的[w]大体上是/b/的可预测实现，而不是一种对立，而原则3说可预测的音位变体不设字母，这与§8中统一`k`的理由相同。如果`w`能赢得一席之地，那也将是借词为它赢得的。

凡是要加入这个组的东西都受一条限制性原则约束：这个音必须能为其使用者区分词，西里尔字母必须无法表示它，而且它必须无法从语境预测。`ä`三项全部通过，是这个组中最有力的一个。`x`不符合第一项，因为它的[h]和[x]随说话人和地区而变，而不随词而变。`w`不符合第三项。

# 第三部分——背景

柯尔克孜语（Кыргыз тили）的拉丁正字法处在音系学、字体排印工程和日常数字实践的交汇处，而这个问题并非假设。2024年9月，在巴库举行的一次会议上，在突厥学院和突厥国家组织框架下工作的突厥世界通用字母委员会，商定了一套拟议的34字母通用突厥语字母（CTA）[[1]](#ref1)[[2]](#ref2)。吉尔吉斯斯坦是唯一一个尚未决定放弃西里尔字母的突厥国家组织成员国[[2]](#ref2)，而代表该国出席这些会谈的柯尔克孜语言学家瑟尔特拜·穆萨耶夫曾表示，一份柯尔克孜语28字母拉丁字母草案已经准备就绪，正等待总统和议会作出政治决定[[2]](#ref2)[[3]](#ref3)。萨德尔·扎帕罗夫（Sadyr Japarov）总统表明的立场是：现在讨论过渡为时过早，国家语言的发展应当继续使用西里尔字母[[3]](#ref3)。

## 21. Jany-Latyn与现有系统的关系

### 21.1 现有的柯尔克孜语罗马化方案

柯尔克孜语没有一种普遍接受的罗马化方案；对于地理名称，政府采用了BGN/PCGN[[8]](#ref8)。有四种系统在流通，Jany-Latyn与它们各自的关系各不相同。

| 西里尔字母 | BGN/PCGN | ALA-LC | ISO 9 | CTA | **Jany-Latyn** |
| :---: | :---: | :---: | :---: | :---: | :---: |
| ж | j | zh | ž | c | **j** |
| й | y | ĭ | j | y | **í** |
| ы | y | y | y | ı | **y** |
| ң | ng | n͡g | ņ | ñ | **ŋ** |
| ө | ö | ȯ | ô | ö | **ö** |
| ү | ü | u̇ | ù | ü | **ü** |
| ч | ch | ch | č | ç | **ç** |
| ш | sh | sh | š | ş | **ş** |
| х | kh | kh | h | h | **h** |
| ъ / ь | ˮ / ʼ | ʺ / ʹ | ʺ / ʹ | ʺ / ʹ | *（吸收或删除）* |

（BGN/PCGN、ALA-LC、ISO 9和CTA各列据[[8]](#ref8)。）

**BGN/PCGN**是在吉尔吉斯斯坦具有官方地位的系统，Jany-Latyn在对辨识度最重要的字母上与它一致：用`j`表示`ж`，用`ö`/`ü`表示前圆唇元音。它是为外国读者设计的转录方案，而不是正字法，这一点显而易见：它把`й`和`ы`都写作`y`，因此*тыйын*成为*tyyyn*，而它的二合字母`ch`、`sh`、`kh`、`ng`在语素边界上相互冲突。它的长处是除了`ö`和`ü`之外不需要任何字母；它的短处是从来不是为了让柯尔克孜语使用者书写而设计的。

**ALA-LC**是一种图书馆编目标准，它以组合符号（`n͡g`、`u̇`、`ĭ`）为手段，以可逆性为优化目标。它是唯一一个在滑音问题上与Jany-Latyn直觉相同的系统，把`й`写作`ĭ`，即`i`上加一个符号。但它的组合附加符号规范化起来不一致，也无法在普通键盘上键入。

**ISO 9**是一种机械的西里尔字母—拉丁字母映射，旨在通用于整个文字，而非针对特定语言。它把`й`写作`j`，把`ж`写作`ž`，而从一种`ж`是[dʒ]的语言的角度看，这恰恰是颠倒的。它往返转换完美，读起来却很糟，这对书目标准来说是一个合理的取舍，对正字法来说则不是。

**CTA**在§21.2中讨论。

Jany-Latyn与这四种系统的差异都源于一个不同的目标。这些系统是把柯尔克孜语转写*成*拉丁字母，供读其他文字的人使用。Jany-Latyn则旨在让以柯尔克孜语为母语的人能凭直觉阅读。

### 21.2 通用突厥语字母

2024年9月在巴库商定的34字母CTA[[1]](#ref1)[[2]](#ref2)旨在作为整个突厥语世界的共同基础，由各国分别加以本国化调整[[3]](#ref3)。凡是柯尔克孜语音系支持之处，Jany-Latyn都与CTA的功能核心一致（`ö`、`ü`、`ç`和`ş`全部相同）。有六个字母不同，每一个都在第二部分中论证：`й`（§10）、`ж`（§11）、`ы`（§9）、`к`和`г`（§8），以及`ң`（§14）。

**`í`用在CTA用`y`的地方**。CTA可以把`y`用于滑音，因为它把`ы`移到了无点`ı`上；Jany-Latyn已经把`y`用于`ы`（§10）。

Jany-Latyn从当前的柯尔克孜语用法出发，并接受CTA所提供的大部分趋同。CTA的34个字母中有三个在柯尔克孜语中无事可做：`Ə`是该元音系统之外的元音，`Ū`是哈萨克语的`ұ`，而在`х`写作`h`的地方`X`是多余的。在其余31个字母中，Jany-Latyn采用了26个，其中包括`ç`、`ş`、`ö`和`ü`（§17.3）。它拒绝了四个：`c`（§11）以及`q`和`ğ`（§8），原因是词表依赖；`ı`，原因是大小写转换和小字号对它的影响（§9）；它还用`ŋ`取代了CTA的`ñ`（§14）；把`ы`写作`y`也消除了对带点大写字母`İ`的任何需要。用`ŋ`代替`ñ`，再加上`í`——这是Jany-Latyn所有、而CTA在任何形式上都没有的唯一一个字母——字母表共计28个字母，而这一差别是一组决定，而不是一种欠缺。哈萨克语的选择也以同样的方式权衡过，`ū`或`ұ`以及保留西里尔字母`ө`的做法都被搁置，而选用了共同的`ü`和`ö`（§12.1）。每一个被拒绝的字母都保留在试验场中，试验场的对齐CTA预设方案把它们全部采用以达到完整的31个，因此部分采用或全盘采用都只是一种设置，而不是一个分叉，并且可以在同一段文本上与Jany-Latyn对照评判。

除了字母之外，不全盘采用CTA的论证是结构性的。柯尔克孜语有土耳其语所没有的音位性元音长度；柯尔克孜语的`ж`是塞擦音，而土耳其语的`j`是擦音；哈萨克语经历了柯尔克孜语所没有经历的咝音变化。一种针对其自身音系调整的正字法，会在音系一致之处与泛突厥标准一致，在音系不一致之处与之分道扬镳，而这正是上面所呈现的模式。CTA本身也预见到了这一点：巴库会议的一位与会者指出，不需要全部34个字母的语言可以使这套字母表适应自身[[3]](#ref3)。

还有一种并非语言学上的代价：与土耳其语、阿塞拜疆语或乌兹别克语几乎相同的拼写，会消除机器用来分辨一种较小语言的信号。§22讨论了这一点，以及支持趋同的理由。

#### 各系统中的同一批词

只用固有词汇，以免这里的任何东西取决于转换器如何处理借词。是否写`q`是一个词表问题，而不是一个字母表问题。

| кыргыз | kyrgyz | qyrğyz | qırğız | qırğız |

在连续文本中：

> **西里尔字母**。Адамдардын бир-бири менен алмашкан каттары, эл аралык иммуногистохимия же башка техникалык журналдарда чыккан изилдөө макалалар, элге белгилүү болгон ырлар жана чыгармалар — баары бир алфавитте жазылат.
>
> **Jany-Latyn**。Adamdardyn bir-biri menen almaşkan kattary, el aralyk immunogistohimiía je başka tehnikalyk jurnaldarda çykkan izildöö makalalar, elge belgilüü bolgon yrlar jana çygarmalar — baary bir alfavitte jazylat.
>
> **q+ğ**。Adamdardyn bir-biri menen almaşqan qattary, el aralyq immunogistohimiía je başqa tehnikalyq jurnaldarda çyqqan izildöö maqalalar, elge belgilüü bolğon yrlar jana çyğarmalar — baary bir alfavitte jazylat.
>
> **q+ğ+ı**。Adamdardın bir-biri menen almaşqan qattarı, el aralıq immunogistohimiya je başqa tehnikalıq jurnaldarda çıqqan izildöö maqalalar, elge belgilüü bolğon ırlar jana çığarmalar — baarı bir alfavitte jazılat.
>
> **对齐CTA**。Adamdardın bir-biri menen almaşqan qattarı, el aralıq immunogistohimiya ce başqa tehnikalıq jurnaldarda çıqqan izildöö maqalalar, elge belgilüü bolğon ırlar cana çığarmalar — baarı bir alfavitte cazılat.

对齐CTA的这一行是按一个掌握词表的人会写的样子写的：固有词的`ж`写作`c`（*ce*、*cana*、*cazılat*），借词的`ж`写作`j`（*jurnaldarda*），固有的后和谐`г`写作`ğ`（*bolğon*、*çığarmalar*），而借词保留普通的`g`。试验场可以复现这一行的其他所有特征。它无法生成的，是`c`模式文本中的*jurnaldarda*：这种文本把每个`ж`都写作`c`，得出*curnaldarda*；只有知道哪些词是俄语借词，才能弥合这一差距。

这段文字的构造是为了让各配置明显不同，而不是为了读起来优美；其中有两个词值得逐行追踪。

- *Техникалык*在一个词内部展示了`k`与`q`的对比：在`q`各行中它是*tehnikalyq*，借词词干的软腭音`k`旁边是固有后缀的小舌音`q`。一条读取最近元音的规则碰巧能把它处理对，正如它对*immunogistohimiía*中普通的`g`与固有词*bolğon*的处理一样，但没有任何东西告诉这条规则*tehnika*是借词，这就是为什么同样的启发式规则也会产生*qosmos*和*parq*。
- *Immunogistohimiía*展示了各系统如何处理该语言不断吸收的词汇：`h`表示`х`，`ía`表示词末的`я`，双写辅音保持完整，而且这个词足够长，辨读性和排序都必须在整个词上站得住。

### 21.3 穆萨耶夫的历史复兴

瑟尔特拜·穆萨耶夫是I.阿拉巴耶夫柯尔克孜国立大学语言学研究所所长，也是吉尔吉斯斯坦出席2024年巴库会谈的代表之一，他提出一套建立在特内斯塔诺夫方案基础上的28字母拉丁字母表，认为它完整地保留了柯尔克孜语的音位结构，因此不会带来任何语言学问题[[3]](#ref3)。

这两个提案的一致之处多于分歧之处。二者都使用`ö`、`ü`、`ç`、`ş`，也都用`y`表示`ы`[[3]](#ref3)。分歧源于他的方案是一种复兴，而本方案是一种全新的设计：他的字母表恢复了特内斯塔诺夫字母表中的`k`/`q`拆分，追随特内斯塔诺夫和CTA把`ж`写作`c`，并用`ņ`而不是eng来标记软腭鼻音。二者出于同样的理由给同一个基字加标记，只是手段不同：`ņ`是在`n`下方附加一个下加符，而`ŋ`和特内斯塔诺夫的`ꞑ`则让字母本身的笔画延伸到基线以下。`ŋ`在字体支持和国际音标支持方面也是二者中较好的。

更具影响的差别并不在语言学上。穆萨耶夫的提案有一条可信的成为法律的途径，而本项目既没有、也不声称有这样的途径。Jany-Latyn的贡献在另一个方向上。它今天就以可运行的软件存在，其工程设计针对的是一套20世纪20年代的字母表从未打算回答的问题：确定性的西里尔字母往返转换、分词、搜索折叠，以及一种ASCII简易形式。两个提案并不是在争夺同一份工作。

### 21.4 国内的其他提案

穆萨耶夫的方案并不是唯一的柯尔克孜语拉丁字母项目。发布在qyrgyz.com上的一套30字母字母表，在历史学家滕奇特克别克·乔罗捷金（Tynchtykbek Chorotegin）等人的参与下制定，它同样从20世纪30年代的拉丁字母出发，但对其中的罕用字母作了现代化处理：用`Ğ`取代`Ƣ`，用`Y`取代`Ь`，并把`Ꞑ`、`Ɵ`和`Y`规范为`Ñ`、`Ö`和`Ü`[[12]](#ref12)。

Jany-Latyn在用`Y`表示`ы`以及`Ö`和`Ü`上与它一致：这是三个独立项目各自汇合的三点。它在`Ğ`和`Ñ`上与之分歧，而两处的理由不同。`Ğ`在一种复兴中得以保留，是因为特内斯塔诺夫的字母表有`Ƣ`；它过不了原则1这一关。`Ñ`则较难决断，因为两个项目都在对同一个字母——特内斯塔诺夫的`Ꞑ`——作现代化处理，分歧在于用什么来取代它：`Ñ`把符号以波浪符的形式移到字母上方，而`Ŋ`保留向下延伸的笔画。把两种结论分开的是出发点，而不是音系，两个项目对音系的解读是相同的。

### 21.5 哈萨克斯坦和乌兹别克斯坦说明了什么

哈萨克斯坦是现有的最有用的比较对象，因为它展示了一套字母表在法令与日常使用之间会遭遇什么。2017年的法令引入了一套以撇号为基础、受到广泛嘲笑的字母表；2018年2月，第二道法令用尖音符取代了撇号[[13]](#ref13)；尖音符版本本身也受到批评，部分是由于其中的尖音符和保留的二合字母[[14]](#ref14)；2021年，进一步的修订定为31个字母，使用变音符、长音符、短音符和下加符——`ä`、`ö`、`ü`、`ū`、`ğ`、`ş`[[5]](#ref5)。即使在2021年之内，软腭鼻音也在1月版和4月版之间从`Ŋ`改成了`Ñ`[[9]](#ref9)。完成日期已从2025年改为2031年[[15]](#ref15)。乌兹别克斯坦于1993年开始其过渡，至今仍未完成[[3]](#ref3)，2021年的一份修订草案仍保留二合字母`ng`[[9]](#ref9)。

有三条教训可以带入本文。看似已定的字母层面的决定会被重新提出，这是支持发布试验场而非发布法令的一个理由。附加符号系统在公众面前是按其大量出现时的观感来评判的，音系逻辑很少进入争论。而采用一套字母表与用它书写之间的差距，要以几十年来衡量。

吉尔吉斯斯坦有自己版本的第三条教训，而且近在本国：2004年通过的一项正字法改革，因公众没有接受而被撤回[[3]](#ref3)。

## 22. 社会语言学与政治背景

### 22.1 离开西里尔字母的政治

柯尔克孜语在一个世纪内两次更换字母：1928年从阿拉伯字母改为拉丁字母，1940年从拉丁字母改为西里尔字母。下一次更换如果到来，其起因是政治性的，而不是学术性的。穆萨耶夫的概括是：字母表和正字法由最高议会（Jogorku Kenesh）的决议通过，并需要总统令，学者只能提出建议[[3]](#ref3)。2023年4月，国家语言全国委员会主席告诉议会，如果作出政治决定，学者和公众已准备好转向拉丁字母，此后总统公开训斥了他，并表示这一讨论为时过早，国家语言的发展应当继续使用西里尔字母[[3]](#ref3)。几天后，俄罗斯暂停了从吉尔吉斯斯坦进口乳制品[[18]](#ref18)。无论这一转变在柯尔克孜语使用者看来多么不可避免，它都被解读为背离莫斯科，而回应则以贸易政策的形式到来。

### 22.2 共同的突厥语标准让一种较小的语言付出什么

莫斯科对拉丁字母过渡的解读，在公共场合不断被争论；另一种选择的代价却没有。全盘采用通用突厥语字母，会使柯尔克孜语与该语族中最大的书面标准对齐，而较小的语言要为这种对齐付出的，是书面上使它区别于邻居的一切。

西里尔字母以两种方式标记这种区别。相对于土耳其语和其他以拉丁字母书写的突厥语言，文字本身就是标签。相对于共用同一文字的哈萨克语，起这一作用的是字母：哈萨克语写`ә`、`і`、`қ`、`ғ`、`ұ`和`һ`，柯尔克孜语一个都不写，也不写任何哈萨克语所缺的字母[[4]](#ref4)[[15]](#ref15)，因此柯尔克孜语只是靠缺少什么来标记。从一个共同模板中取来的拉丁字母表，会对每一个使用拉丁字母的邻居消除第一种信号，而第二种信号则留给每种语言各自保留下来的自有字母。

损失显现在短字符串上。标题、名字、话题标签、元数据和查询几乎不带信号，因此不论由什么来判别它们，都只能退回到先验概率，而先验概率取决于语料库规模，语料库规模又取决于用该语言书写的人数。柯尔克孜语的使用者比土耳其语少一个数量级，也比哈萨克语少，因此在本节所作的两种比较中，它都是较小的一方。Jany-Latyn把*кылым*（世纪）写作`kylym`，这个字符串不属于任何其他语言；对齐CTA的设置把它写作`qılım`，而这在阿塞拜疆语中是动词*qılmaq*（做）的一个形式。2026年9月在Google上搜索，`qılım`返回的是那个动词，而西里尔字母的*кылым*返回的是柯尔克孜语的这个词。含有*жаным*的歌名面临同样的分岔：`janym`是柯尔克孜语，而`canım`是土耳其语。

较长的文本更安全，其余量取决于语言间的距离。相对于土耳其语，没有什么风险：无论用什么字母，一段柯尔克孜语都能被认出来，因为词汇和形态的分歧比拼写更大。相对于哈萨克语，余量就窄一些，因为两种语言足够接近，词汇区分它们就不那么可靠，在共同模板之下，一段文本要更长才能表明自己的身份。这是关于工具的事实，而不是对亲缘关系的抱怨。在这两种情况下，效应都集中在短字符串和自动标注上；§23.2说明了如何测量它，以及为什么目前只能进行与土耳其语的比较。

在训练语料库的构建处，损失会叠加，因为网络爬取的数据在能被使用之前必须先按语言分类，而负责分类的东西只能依据文本本身。西里尔字母柯尔克孜语一眼就能与土耳其语区分开，凭字母也能与哈萨克语区分开；而形似其邻居的拉丁字母柯尔克孜语会被归为其中之一，从一个本已单薄的语料库中被减去，又作为噪声被加到一个更大的语料库中。一种难以找到的语言是不方便的；一种在收集环节就被贴错标签的语言，则停止积累。

语音识别和语音合成取自同样的语料分组，而在信号最弱的地方，错误已经可以听见。柯尔克孜语西里尔字母相对于哈萨克语，只靠它不使用的字母来标记，这一标记薄弱到今天就可能被当作哈萨克语：2026年9月，作者把柯尔克孜语歌词交给Suno V6-mini，它按哈萨克语的读音唱给作者听，把`ж`唱成擦音[ʒ]而不是柯尔克孜语的塞擦音[dʒ]，同时还有`к`和`г`的软腭音和小舌音读法。一个在收集环节被贴错标签的语料库，最后会变成一个把柯尔克孜语当作某个邻居语言的近似物来处理的助手，而孩子们最早遇到这一点，他们学习阅读时所对照的，是周围的工具当作正确的任何东西。

任何向拉丁字母的转变都会放弃西里尔字母免费提供的一种信号，而在各种拉丁字母正字法之间的选择，决定了这一信号有多少能保留下来。目前使用中的突厥语拉丁字母正字法，没有一种写`ŋ`，也没有一种写`í`，因此`jaŋy`和`kylym`自带语言标签，而`cañı`和`qılım`则没有。这一性质并不是设计目标。它源于出于其他理由——为滑音、软腭鼻音和`ы`——作出的选择，因此它是作为一项有待检验的预测提出的，而绝不是作为那些选择的理由。

### 22.3 亲属语言，共享的字母

柯尔克孜语与土耳其语的区别无需多加阐述：二者属于该语族的不同分支，彼此不能互通，即克洛斯（Kloss）所说的Abstand[[19]](#ref19)。仅靠拼写无法消除这段距离。哈萨克语在每个尺度上都更近——同一分支、共同继承的核心、几个世纪的接触——因此在书面上把二者分开的东西，较少来自语言本身，较多来自它们各自的标准，而字母表是其中的一部分。这就是为什么那里的识别余量更窄。在两种情况下，一种正字法不予记录的区别都会失去一种使它保持下来的支撑，而经过足够长的时间，这可能波及口语。

柯尔克孜语已有大半个世纪与一种强势语言共用一种文字，有用的比较是这种接触做了什么、没有做什么。俄语规范随俄语词进入柯尔克孜语西里尔字母，也止步于此，这就是为什么`ц`、`щ`、`ъ`、`ь`和j化的`е`在柯尔克孜语中是仅用于借词的字母，也是为什么转换器可以承受丢失它们。这种接触并不是单方面的损失：它大大丰富了词汇，而随借词而来的规则停留在借词层中，因为俄语在柯尔克孜语固有词中没有同源词可供其规则施加作用。

土耳其语并不处于那种位置。它与柯尔克孜语共有突厥语族词汇的继承核心[[26]](#ref26)，而它的惯例正是CTA所规定的惯例，因此与它共用的书面标准会带来直接作用于固有词的规则——而这样一种标准所提供的好处，即语族内更便利的相互借用和更大的共享技术词汇库，与那种风险经由同一条渠道到来。凡是这条渠道在亲缘关系密切的语言之间敞开的地方，案例都指向同一个方向。1933年的苏联改革使乌克兰语和白俄罗斯语的拼写向俄语靠拢，去掉了乌克兰语字母`ґ`，直至1990年[[22]](#ref22)[[23]](#ref23)。按西班牙语惯例书写的加利西亚语，长期伴随着关于卡斯蒂利亚化的争论[[24]](#ref24)，而用英语拼写书写的低地苏格兰语读起来像拼错了的英语[[25]](#ref25)。

日常的机制是纠正。以较大语言训练的拼写检查器和查询规范化，会把较小的语言纠正成较大的语言；一个被要求写柯尔克孜语的模型，在正字法给它机会的地方，会用土耳其语填补空缺；书写者则会把那些相对于他们每天阅读的另一种语言看起来像是错误的词形规范化。这所预测的偏移，首先发生在词汇和书面规范上，只会经由上述途径才进入口语。

这些是倾向，而不是必然。一种强势书面标准能传播多远，取决于不止两种语言之间的亲缘关系：取决于接触持续多久，取决于其间学校教育、媒体和政策做了什么，也取决于双方各自带来多少文本和工具。本文对这些都没有测量。正字法是若干力量中的一种，其中没有哪一种能单独起决定作用[[28]](#ref28)。

### 22.4 熟悉度与采纳

一套字母表是由并没有要求它的人们来采纳的，他们先接触到它的字母，然后才接触到它的论证。哈萨克斯坦更换了两套在公众面前按其外观被评判的字母表，而吉尔吉斯斯坦在读者没有接受时撤回了它自己2004年的改革（§21.5）。一个新字母设计起来花费很少，教起来却花费很多，而这一代价同时落在每一位读者身上。

以柯尔克孜读者已经知道的东西来衡量，有几个CTA字母是新的：用`c`表示`ж`，无点`ı`配带点`İ`，以及`ğ`，它在1940年以来使用的任何柯尔克孜文字中都没有对应。每一个对土耳其语读者来说都是熟悉的，而这正是CTA据以构建的熟悉度。

标牌和随意书写是最先遇到这一点的地方，遇到它的读者完全没有受过任何指导，而一个面对陌生正字法的读者，会先注意基本字母，后注意附加符号，并按已知的读音来读它们。在对齐CTA的设置中，*жарыя*（通告）写作`CARIYA`，一个没有学过`c`是[dʒ]的读者会把它念成*кария*或*сария*；两者都不是标牌上的那个词，而字符串中也没有任何东西提示这一错误。*Чыгуу*（出口）成为`ÇIĞUU`，那位读者会把它当作`CIGUU`，也就是简易形式直接写出的拼写。若按`C`和`I`的西里尔字母读音来读，公共标牌上最常见的词之一就成了粗话。Jany-Latyn的`ÇYGUU`可能在一个字母上造成误导，即`C`对应`ч`；CTA的拼写又增加了第二个，即`I`对应`ы`。

这些代价是过渡性的，一旦字母被教授就会结束；这是一个有国家支持的标准能够给出的回答。过渡期很长，在两个邻国都要以几十年计。一种正字法正是在这段过渡期内被评判的，而正字法的制定把读者的接受度本身当作一项设计标准[[27]](#ref27)。

Jany-Latyn则依靠柯尔克孜读者已经具有的两种熟悉度。一种是他们所读的西里尔字母：`í`是带符号的`i`，正如`й`是带符号的`и`；`ŋ`保留了`ң`的下伸笔画；长度像在西里尔字母中一样双写。另一种是他们已经在键入和看到的拉丁字母：护照拼写*Japarov*和地名*Jalal-Abad*中的`j`，该国英文国名中的`y`，以及与人们现在发短信的方式相符的简易形式。这两种熟悉度沿着代际界线分布，因为在西里尔字母教育中长大的读者熟悉前者，在手机键盘上长大的读者熟悉后者，而这些字母的选择使它们从两边都能被认出来。

`ŋ`是两者分道扬镳的地方。它的熟悉度在于形状——对读过`ң`的读者而言——而较少在于键盘：`ŋ`在一些长按菜单上，`ñ`几乎在所有长按菜单上。这就是为什么`ñ`作为一种对照设置提供（§14）。在其他每一处，柯尔克孜读者会猜到的字母，就是该正字法所写的字母。

### 22.5 支持趋同的理由，以及本文所持的立场

趋同是CTA的意义所在，与已经用拉丁字母书写的突厥语言相互可读是一种真实的好处；这是在这里值得考虑拉丁字母表的三个理由之一。另外两个理由随任何拉丁字母正字法而来，无论它与什么对齐：拉丁字母是国际读者已经在读的文字，也是键盘、编码和文本工具围绕其构建的文字。只有第一个理由是通过遵从CTA换来的，这使问题变成了遵从到什么程度，而不是要不要用拉丁字母。

对哈萨克语而言，这种好处并不新鲜。二者已经能读对方的西里尔字母，而且都派代表出席了商定通用突厥语字母的巴库会谈。哈萨克斯坦此后已经颁令并确定日期，进行自己的拉丁字母过渡（§21.5）；吉尔吉斯斯坦尚未决定转换。一次过渡所决定的，是这种联系能否延续下去。如果二者都建立在共同的拉丁字母基础上，联系就能保持；如果一方转换而另一方不转换，联系只能维持到同时认识两种文字的读者还在的时候；如果双方都转换但分歧比它们的西里尔字母更大，联系就会变薄。Jany-Latyn的目标是让这两种语言在拉丁字母中像在西里尔字母中一样彼此可读，而它的引擎和试验场可以被分叉，为哈萨克语运行同样的评估。二者相互靠近到什么程度，是在两个方向上共享其遗产的姊妹语言之间的事。来自第三种语言的惯例是另一个问题。CTA的`c`和`ı`沿用土耳其语的用法，只有在它们经得起§22.3的语言转用风险和本文各项论证的检验时，才值得采用，而不是默认采用。

拒绝该标准的某些部分（§21.2）并不会使柯尔克孜语成为例外，因为没有一个突厥语国家全盘采用了它。土库曼语出于与本正字法写`í`相同的结构性原因把滑音写作`ý`，并在CTA用`ñ`的地方把软腭鼻音写作`ň`[[20]](#ref20)；乌兹别克斯坦的草案保留二合字母`ng`；哈萨克斯坦在2021年之内两次修订了自己的字母。共同的拉丁字母基础从来不要求其上有共同的符号：欧洲的拉丁字母语言——其中包括日耳曼、罗曼、斯拉夫、波罗的和乌拉尔诸语言——都建立在同样的26个字母上，却在其上没有一套共同的附加符号，邻近语言之间拼写各异是常态[[21]](#ref21)。最近的先例就在本国。柯尔克孜语和哈萨克语的西里尔字母共用一个基础，各自保留自己的字母，二者既彼此可读，又在书面上保持区别：哈萨克语靠它增加的字母，柯尔克孜语靠这些字母的缺席。对于拉丁字母过渡来说，这种关系值得记取，尽管它并不是过渡的条件。

通用突厥语字母可以容纳本文所论证的每一种区别。代价是：更多的字母；一份持续维护的借词词表以及维护它的机构；还有教授没有任何柯尔克孜读者见过的字形的成本。一个有国家支持的标准能够承担前两项。第三项无论其余由谁承担，都落在读者身上。Jany-Latyn的构建使它前两项都不需要，第三项也尽可能少。

一种语言值得以它已经在使用的形式书写，而一个地区性标准，在能保持较小语言可辨识的范围内，值得加入，因为趋同若追求得足够远，留下的将是更少的不同书面语言，而不是更多相互可读的语言。这些是立场，而不是实证结果，而那个界限在哪里，要由§23.2的检验来测量。二者都不是在为纯洁性辩护：日常柯尔克孜语词汇中有很大一部分源自俄语，而无论什么取代西里尔字母，都会带来它自己的借词。关切的范围更窄：一种可能使这一语言更难被找到、更容易被归为另一种语言的变化，一种首先显现在机器层面、在那里最不易被察觉的损失。另一种负担则公开落在读者身上，他们被要求学习一套自己并未选择的字母表和惯例，而这一负担适用于本文所论证的字母，正如适用于其他任何字母。这两种负担是否值得承受，以及过渡朝哪个方向走，要由柯尔克孜人来决定。

### 22.6 代价与制约

- **成本与能力**。国内反对拉丁化的一个反复出现的理由是：它代价高昂，而教育有更紧迫的需要。这一反对意见是严肃的，更好的字母设计并不能回应它。
- **多语国家**。吉尔吉斯斯坦不是单语国家。俄语具有官方地位，乌兹别克、东干和其他群体用西里尔字母书写。柯尔克孜语向拉丁字母的过渡不会带动这些语言，因此无论柯尔克孜语发生什么，西里尔字母都仍将在日常中使用。任何现实的计划都是共存的计划，而不是替代的计划，这也是支持一个能双向运行的转换器的理由。
- **地缘政治**。一方面是莫斯科的反应，另一方面是共同的突厥语标准的吸引力，二者都对国家层面的过渡构成压力。它们都不制约一个无需任何决定就能发挥作用的工具。
- **代际不对称**。在西里尔字母教育中长大的读者和在手机键盘上长大的读者，起点是不同的字母，而两种语域正是为此而设：完整形式用于印刷品和课堂，简易形式用于手机。

# 第四部分——开放问题与治理

## 23. 开放问题与今后的工作

其中有些是试验场旨在支持的实验；其余的是尚未完成的规范工作。每项实验都说明其论断、能够判定它的检验，以及会构成反证的结果。

### 23.1 分词

**论断**：单一的拉丁字母编码比混合文字的文本分词效率更高，并且与西里尔字母相当或优于西里尔字母。

**检验**：取一个固定的语料库（柯尔克孜语维基百科，或者为得到干净的平行语料而用FLORES-200 `kir_Cyrl`），以西里尔字母、Jany-Latyn、对齐CTA的设置和一种混合文字配置分别呈现，并在若干分词器下测量每词的词元数。

**什么会推翻它**：在广泛使用的模型中，拉丁字母柯尔克孜语的分词效果*差于*西里尔字母。这是一个合理可能的结果，因为西里尔字母柯尔克孜语在训练数据中的代表性远远高于任何拉丁字母柯尔克孜语，而如果发现这种情况，就需要报告。

### 23.2 语种识别与检索

**论断**：在正字法上与拉丁字母突厥语标准拉开距离，可以使柯尔克孜语对机器而言保持可识别，而且文本越短，这一效应越大（§22.2）。

**范围**：在§22.2的两种比较中，只有与土耳其语、阿塞拜疆语和乌兹别克语的比较现在就能检验，因为这些语言如今用拉丁字母书写。拉丁字母哈萨克语是更近的情形（§22.3），它存在于法令和样张字表中，在其过渡于2031年结束之前不会被大量书写（§21.5）。转写一个西里尔字母哈萨克语语料库，检验的是转写器而不是这种语言，因此与哈萨克语的比较仍停留在论证层面，只有下面的第三项检验能触及它。

**检验**：共四项，按成本递增排列。

1. *碰撞统计*。在Jany-Latyn和对齐CTA的设置下，统计与土耳其语、阿塞拜疆语或乌兹别克语词型相同的柯尔克孜语词型数量。它只需要词表，并直接测量这一机制。
2. *识别与字符串长度*。用现成的识别器，如fastText的`lid.176`或GlotLID，在两种配置下对同一段柯尔克孜语文本，分别以1、3、5、20和100个词元的长度运行识别。预测是：两种配置在段落上结果一致，而随着字符串变短而分化。
3. *黑箱观察*。把每种配置下的同一段文本交给已部署的系统——网络搜索引擎、识别器、语音或歌曲合成器——并记录每个系统以哪种语言作答。这是本文中最弱的证据：这些系统是不透明的，并且会在不通知的情况下变化，因此每一项观察都带有日期和系统所公开的任何版本信息，而且不说明系统为什么这样作答。§22.2中的Google搜索和Suno演唱就是这类观察。
4. *生成式侵入*。让模型以每种配置生成柯尔克孜语散文，统计每千词中的土耳其语和哈萨克语词项，不计柯尔克孜语和哈萨克语共同继承的词汇（§22.3）。

**什么会推翻它**：碰撞率可以忽略不计，或者在两种配置下识别在三个词元时都仍然可靠；如果发现其中任何一种，都需要报告。在拉丁字母哈萨克语文本出现之前，与哈萨克语的比较没有反驳条件。

### 23.3 简易形式的合并

**论断**：去除符号的备用形式所合并的词（`baş`与`bas`、`aş`与`as`）在真实文本中足够少，因此它在一致性和折叠上的优势超过这些合并（§19）。

**检验**：在一个语料库上统计每种ASCII备用形式（`c/s`对`ch/sh`）合并的不同词型数，并把两个数字与按词类统计的往返损失率一起报告。

**什么会推翻它**：去除符号的映射使明显更大比例的词型坍缩，或者使语境无法区分的高频词对坍缩。

### 23.4 渲染

**论断**：行内的西里尔字母`ө`在视觉上与周围的拉丁字母文本不一致，而与字体是否涵盖西里尔字母无关（§12.2）。

**检验**：在一组常见的界面字体、网页字体和衬线字体中渲染`kөl`和`köl`，并记录词中字形相对于相邻拉丁小写字母的x字高比例、笔画粗细以及任何基线偏移。报告哪些字体进行了替换，哪些只是不匹配。

**什么会推翻它**：在广泛使用的字体栈中，度量与拉丁小写字母相差在百分之几以内，而替换仅限于确实缺少西里尔字母的字体。

### 23.5 输入

**论断**：完整形式可以以正常速度键入：在桌面布局上借助定制键位映射，在未经改装的手机键盘上借助长按。

**检验**：在标准布局上，分别在使用和不使用定制键位映射的情况下，以及在未经改装的iOS和安卓键盘上，测量每1000个字符的击键次数和用时；这也是在已确认的那一个区域设置之外检查§14中`ŋ`可用性的地方。

**什么会推翻它**：与二合字母拼写相比持续存在的速度劣势，或者在常见手机键盘上根本无法输入的字母，这将使`ñ`成为未来版本中更好的字母（§14）。

### 23.6 尚未完成的规范工作

- 一种BCP 47语言标签约定（`ky-Latn`，可能附带一个已注册的变体子标签），使文本可以声明它使用的是哪一个系统。
- 一套CLDR转写规则集，这将使该映射可供任何基于CLDR的平台使用。
- 一种用于教学材料和词典的重音标记约定，它不能是尖音符，因为尖音符就是滑音（§10）。
- 字母层面以外的正字法规则：移行、缩略语、俄语人名和姓氏的处理，以及借词是按其俄语来源拼写还是按柯尔克孜语发音拼写的政策。
- 核心规则之外的大写规则。多字符字素（`ía`、`ío`、`íu`、`ts`以及二合字母备用形式）采用源词的大小写模式，因此句首大写得到`Ía`，全大写得到`ÍA`；这一点已经确定。带连字符的名称也已确定：连字符之间的每一部分各自取其大小写，因此：*Ысык-Көл → Ysyk-Köl*；与此相对，*Кызыл-кыя → Kyzyl-kyía*，保留了源文本所写的小写第二部分。剩下的问题范围更窄，而且大体上是风格问题：带后缀的首字母缩略词和首字母词（*ЖОЖдо*），以及驼峰式标识符。
- 搜索折叠是否应把`q`折叠为`k`（附录B）。
- 转换后文本的机器可读版本标记（§24），使文档可以声明是哪一个引擎版本生成了它。
- 一项文档一致性检查，它根据每个示例的上下文推断其方向和配置，而不是像现在这样依赖一份人工整理的列表。
- 手写与教学：这里的一切都还没有在学习者中检验过，而下加符和尖音符在手写中的表现与在印刷字体中不同。

## 24. 治理

这是该正字法的第1版，作为提案而非标准发布，而本项目的结构安排是让分歧带来修改，而不是因受挫而分叉：

- 每一项有争议的选择都是试验场中的一个开关，每一种替代方案都已在代码中实现。
- 托管的试验场在读者回应其同意提示之后，记录读者所选择的配置，以便把实际使用中偏好的分布与论证并列发表。拒绝的读者也会被计数，但不使用Cookie，也不在设备上存储任何标识符。自行托管或课堂部署不记录任何内容；这套统计机制属于托管实例，而不属于软件本身。
- 全部源代码公开，分为三种授权：转换引擎采用MIT许可，可用于任何目的；试验场应用以非商业许可提供源代码，因此可以阅读、修改并部署在课堂中，但不能出售；本文和规范采用CC BY许可。GitHub上接受问题报告、边界情况和语料反例，任何人都可以审阅规范中的映射规则、提出修改或分叉。
- 版本有编号，变更有记录。随转换后的文本一起传递的机器可读版本标记——使文档能够声明是哪一个引擎版本生成了它，并能被安全地重新转换——是自然的下一步，但尚未实现；它列在§23.6中。

预期的失败方式是被证伪，而不是采纳压力。一个引擎损坏柯尔克孜语固有词汇的可复现案例，对本项目而言比赞同更有价值。

## 25. 结论

本文中的每一个选择都首先服从于一个约束：一个Jany-Latyn形式必须能由已经存在的西里尔字母文本计算得出，否则该正字法从一开始就抛弃了它本应承载的语料库。在这一约束之内，一种正字法的成功在于平衡音系忠实度、字体排印的清晰度和键入的人机工效。如今，它还必须经受得住与搜索引擎、分词器和未经改装的键盘的接触。这些就是评判这项工作的标准：下加符和尖音符是否能置身于一行连续的柯尔克孜语中而不扰乱它，`ŋ`在阅读字号下是否与`n`保持区别，母语者是否会遇到任何歧义，同一段文本是否能经受住往返转换、索引和手机键盘。这些问题最好在一页真实的散文上而不是在精心挑选的例子上解决，而这正是试验场的用途。

在特内斯塔诺夫的拉丁字母表问世一个世纪之后，同一条历史脉络贯穿于穆萨耶夫的草案之中，而这份草案正在等待一个可能不会很快到来的政治决定[[3]](#ref3)。本项目不需要等待那个决定。它的构建使它在有人打开代码仓库的那一刻就能派上用场，所依据的正是柯尔克孜语使用者多年来一直书写拉丁字母的方式：非正式地、不一致地、持续不断地。

诚邀语言学家、工程师和政策制定者检验这些选择，而不是凭信任接受它们：打开试验场，阅读`docs/SPEC.md`中的映射规则，并为引擎处理错误的任何情况提交问题报告。

*Zamanbap, erkin jana tabigyí jazuu egemen elibizge sanariptik doorunda kyzmat kylsyn.*
*（愿一种现代、开放而自然的正字法在数字时代为我们独立的人民服务。）*

# 附录

## 附录A：`e`系统

`э`/`е`/滑音系统是本正字法中最不直观的部分，因此在这里完整地给出算法：

1. **正向**。j化借词中词首或元音后的`е` → `íe`。双写：`ээ` → `ee`。词首的`э` → `e`。辅音后的`е` → `e`。非j化借词中元音后的`э` → `e`。
2. **反向**。`ee` → `ээ`。词首的`e` → `э`。辅音后的`e` → `е`。元音后的`e` → `е`。`íe`按§18.1中的表格处理。
3. **滑音**。`í` → `й`，适用于上述已处理序列以外的所有地方。旧式的`iy`/`iyi`输入（*biyik*）在反向转换时被接受，但它不是Jany-Latyn的输出。
4. **j化**。`ía → я`、`ío → ё`、`íu → ю`；没有滑音的元音间隙保持普通写法（*diagramma → диаграмма*）。

SPEC.md在其第2节（规则4）和第4.3节中陈述了同样的规则。

## 附录B：规范化、折叠与排序

这些是正字法提案通常略去、而任何实现本正字法的人在第一个下午就会遇到的计算要求：

- **规范化**。转换器的输出采用**规范化形式C（NFC）**[[16]](#ref16)，即只要存在合成码位，就把字母及其符号写成一个码位的Unicode形式。`í`、`ö`和`ü`都有这样的码位，以分离的字母加符号形式到达的输入应当在进入时进行规范化。`ŋ`根本没有分解形式，这一点对下一条很重要。
- **搜索折叠**。单一的`foldKey()`把任一种形式映射到同一个索引键：`ö→o`、`ü→u`、`í→i`、`ç→c`、`ş→s`、`ŋ→n`，然后进行大小写折叠，即Unicode中不区分大小写匹配背后的操作。对于六个完整形式字母中的五个，这正是标准去重音处理已经在做的，因为`ç`、`ş`、`ö`、`ü`和`í`在规范化形式D（NFD）——NFC的分解对应形式——下会分解为基本字母加符号；`ä`以同样的方式折叠为`a`。`ŋ`是完整形式字母中的例外，必须显式处理，因为无论怎样进行Unicode规范化，都无法把它折叠为`n`。同样的例外还有：`ı→i`，就使用它的那些配置而言；`ñ→n`，则不需要单独的规则，因为`ñ`在NFD下会分解为`n`加波浪符。
- **有两种折叠取决于配置**。当§20的直写模式字母启用时，`x→h`、`w→v`，把反向转换有意丢失的区别统一起来，因此搜索*haram*能匹配*xaram*，搜索*tav*能匹配*taw*。未启用时，`x`和`w`是外国名称中的普通拉丁字母，必须折叠为自身：*Linux*、*LAX*和*X Factor*并不是带软腭擦音的柯尔克孜语词，在一个容纳多语言内容的索引中把它们折叠为*linuh*和*lah*是错误的。折叠跟随配置；它不是字母本身的性质。
- **小舌音字母的折叠并不均衡**。`ğ`不需要单独的规则：它在NFD下分解为`g`加短音符，并像`ç`和`ş`一样被去掉符号，因此*bolğon*和*bolgon*落在同一个键上。`q`是一个基本字母，没有什么可去，所以它折叠为自身，*qyz*和*kyz*是两个键。一个同时容纳Jany-Latyn文本和带`q`设置文本的索引，需要一条显式规则来匹配它们：`q→k`；这条规则是否应当放进`foldKey`本身，代价是合并该配置有意书写的一种区别，是一个悬而未决的问题。
- **形式等价对去除符号的备用形式成立**。采用Jany-Latyn的ASCII映射，简易形式*就是*折叠形式，因此`çaí`和`cai`落在同一个键上。在过渡性的二合字母备用形式下，简易形式是`chai`，它会折叠到另一个键，除非索引还应用这两条规则：`ch→c`、`sh→s`。任何为二合字母风格文本建立索引的部署都需要这额外的一对规则；去除符号的备用形式则什么都不需要。
- **排序**。在Unicode排序算法未经定制的顺序下[[6]](#ref6)，`ç`作为`c`的变体排序，`ş`作为`s`的变体排序，这不是柯尔克孜语的字母顺序。Jany-Latyn的区域设置需要一套排序定制，就像土耳其语对`ı`/`i`所作的定制那样。

SPEC.md第5节逐步给出了折叠过程及其选项。

## 附录C：排序定制

规则以Unicode国际组件（ICU）的规则语法给出，通用区域数据存储库（CLDR）、PostgreSQL的ICU排序规则、Java和PyICU都接受这种语法。`&`指出被锚定的字母，`<`标记一级差异（字母表中的一个不同字母），`<<<`标记三级差异（同一字母仅在大小写上不同）。下面第一行应读作：*把`ç`作为一个独立的字母紧接在`c`之后，并把`Ç`当作同一个字母的大写*。其余每一行的原理相同。

```
# Jany-Latyn
&c < ç <<< Ç
&i < í <<< Í
&n < ŋ <<< Ŋ
&o < ö <<< Ö
&s < ş <<< Ş
&u < ü <<< Ü

# Added in the settings with q and ğ
&g < ğ <<< Ğ
&k < q <<< Q

# Added with the ñ setting, which the CTA-aligned setting also uses
&ŋ < ñ <<< Ñ

# Added with the breve or tilde glide options
&í < ĭ <<< Ĭ < ĩ <<< Ĩ

# Added when the extended letters of §20 are enabled
&a < ä <<< Ä

# Replaces the &i rule in the settings with dotless ı; the trailing í applies
# only where the setting keeps the acute glide, since with the y glide
# there is no í to place and Y keeps its default Latin position
&h < ı <<< I < i <<< İ < í <<< Í
```

把`ç`锚定在`c`上而不是放在`b`之后，是有意为之的。`C`不是Jany-Latyn字母表中的字母，但它经常出现在外国名称中，因此把`ç`锚定在它上面，可以使二者相邻排序，而不是让不熟悉的拼写散布在列表各处。替代另一个字母的字母（用`ñ`替代`ŋ`，用`ĭ`或`ĩ`替代`í`）取得被替代字母的位置，紧接在它之后排序。由于没有任何配置同时使用这样一对字母中的两个，所以无论选择哪一个，列表的排序都相同。字母表以外且未被锚定的字母（`w`、`x`，以及在配置不包括它们时的`q`或`c`）保持其默认的拉丁字母位置。**字母表成员资格与排序覆盖范围是两个不同的问题**：教学用的字母表可以省略一个字母，而排序仍必须为它安排位置。

排序是在完整形式上定义的；简易形式文本是ASCII，按ASCII排序，因此`ş`和`s`在那里相互交错。排序与附录B的搜索折叠朝相反的方向用力，一个把另一个合并的东西分开，而一个系统两者都需要。

### 实现说明

`Intl.Collator`不接受自定义定制，因此JavaScript实现无法直接使用上面的规则。参考引擎附带一个由每种配置的显式等级表构建的`compare(a, b)`，并以一份已签入的预期排序结果加以固定；ICU规则则为其他所有平台而发布。
